AI-PET-WORLD
规则生态世界与人格驱动引擎设计文档
V2.0 完整版｜规则生态世界 + 人格驱动行为 + 自主建设文明模拟
0. 文档控制与统一口径
本版文档把“复杂”作为产品优势处理：复杂不是堆概念，而是把生态规律、有限资源、人格差异、自动建设、关系事件和可审计状态变化合成一套可以落地的世界引擎。
1. 一句话定义
AI-PET-WORLD 是一个有生态规律、有限资源、资源循环和自主建设行为的长期运行 AI 世界；玩家不是直接建造者，而是世界源头与观察者；管家和未来生命体根据人格、环境、资源、需求、事件与长期记忆，自主建设、维护并演化家园、社区和小镇。
2. 世界观总原则
世界是自主的，但不是无规律的。沙漠就是沙漠，绿洲就是绿洲，森林就是森林；每种地貌都有自己的资源上限、恢复速度、建设限制、风险事件与生态边界。所谓“自由生成”不是乱生成，而是规则控制下的可复现变化。
世界规律固定：地貌、资源、天气、时间、生态恢复、衰退、建设可行性都有稳定规则。
世界内容非固定：具体布局、建设优先级、房屋形态、道路形态、社区发展路径由 seed、人格、资源、事件和历史共同决定。
世界资源有限：每个世界区域的水、木材、石料、土地容量、食物、能量与生态健康都有上限。
资源会循环：资源会被消耗、转化、恢复、再生，也可能因过度使用而衰退。
建设由生命体发起：家园、社区、小镇由管家与未来居民自主建设和维护，玩家不直接放置对象。
所有变化可审计：任何世界变化都必须以 MapDiff/EventLog/SafeApply 记录，不能凭空改 UI。
3. 世界生态层：地貌与生态规则
地貌不是背景图，而是世界规则的第一层。每个地貌会影响资源存量、恢复速度、可建设类型、风险事件、生命体行为和社区演化方向。
4. 资源系统：有限存量、消耗、恢复与新资源产生
资源不是传统游戏货币，而是世界状态。资源决定建设是否可行、建筑能否维护、社区是否能扩张、生命体是否选择迁徙、休整或延迟某些关系事件。
资源循环规则必须满足守恒意识：任何新增资源都需要来源，例如降雨恢复水、树木成长生成木材、维护行为恢复生态健康、交易带来外部资源。系统可以抽象，但不能让资源凭空无限出现。
ResourceCycleTick = EnvironmentDelta + NaturalRegen + AgentConsumption + ConstructionCost + MaintenanceCost + EventDelta
nextResourceState = clamp(base + regen - consumption - damage + transfer, biomeLimits)
5. 人格驱动引擎
人格不是标签展示，而是行为和建设的概率偏置器。生命信息进入人格核心后，输出的是可工程化使用的向量：建设风格、生活节律、维护偏好、风险容忍度、关系倾向、视觉偏好、长期演化倾向。
人格作用不是决定唯一结果，而是在世界规则允许的范围内改变优先级、概率、顺序和样式。世界规则是硬边界，人格是偏好和决策权重。
6. 人格到房屋与空间组织的映射
“他们会建造自己喜欢的房子”必须工程化为建筑偏好模型。管家不是直接执行“建房子”按钮，而是在资源、地貌、需求、阶段允许时，选择符合自己人格的居住形态和维护方式。
7. 自主建设系统
建设系统的核心不是玩家操作，而是世界内部生命体的自主决策。管家会观察资源、地貌、已有建筑、维护压力、未来机会和自身人格，生成建设意图；系统将意图转成候选计划，再生成 MapDiff，经 SafeApply 后成为世界事实。
HomeMapState + ResourceState + BiomeState + ButlerPersonality + WorldPhase + EventContext
-> ButlerConstructionIntent[]
-> ConstructionPlanCandidates
-> selectedPlan
-> ConstructionExecutionResult(MapDiff candidates)
-> SafeApply
-> nextHomeMapState + EventLog + VisualRefresh
8. 家园、社区、小镇、城镇生态演化
AI-PET-WORLD 的长期目标不是一个静态家园，而是从家园到社区、小镇再到城镇生态的自主演化。玩家不规划城镇；城镇是多主体在资源、道路、关系和公共需求作用下自然形成的。
9. LifeEvent 与伴生生命后置入口
伴生生命/宠物不是默认开局物品。它们只能作为 LifeEvent 与 CompanionDecision 的后置结果出现。某些用户的管家人格、资源状态或世界阶段可能长期不选择接纳伴生生命，这必须被视为正常结果。
10. 状态容器与可审计演化
所有世界事实必须落入结构化容器。没有进入容器的内容不是世界事实；只出现在 UI、CSS、图片或文案中的内容不能被系统视为存在。
11. 关键红线
禁止固定布局模板成为正式主路径；Scene Recipe 只能提供候选关系和约束，不能决定最终画面。
禁止无约束随机；所有生成必须可复现、可审计、可解释。
禁止 UI/CSS/PNG 生成世界事实；图片只能是表现资源，不能反向决定对象存在。
禁止玩家直接建造家园/社区/小镇；玩家只能作为输入源、观察者和有限影响者。
禁止默认生成宠物、pet actor、pet bed、pet_arrival、pet_rest。
禁止资源凭空无限刷新；资源新增必须来自地貌、天气、时间、维护、交易或事件。
禁止人格只停留在文案；人格必须影响行为、建设、维护、关系、空间组织和长期演化。
禁止未审计变化进入 HomeMapState；所有变化必须经 MapDiff/SafeApply 或等价安全链路。

13. 字段级模型：世界规律如何落到工程字段
本节把“世界有规则、资源有限、家园自主建设”拆成可以直接进入 TypeScript schema 的字段。后续开发不得只写抽象概念，所有规则都要能落到状态字段、输入字段、输出字段或审计字段。
14. 地貌规则详细说明
地貌规则必须像“地球状态”一样稳定：不是每次刷新都变，也不是 UI 可以随便换皮。地貌决定资源如何存在、建设是否困难、生命事件是否容易发生。
14.1 沙漠规则
沙漠不是黄色背景，而是一套资源和风险约束。它的水资源稀缺、植物恢复慢、白天高温、夜间温差大，管家在沙漠世界会优先考虑遮蔽、蓄水、储物和减少消耗。
waterCap 低，waterRegenRate 低；rainEvent 可以短期提升水。
woodCap 低，naturalGrowth 低；不允许大面积森林式边界。
shelter 需要抗热/遮蔽属性；开放式花园屋不应作为低资源阶段默认方案。
LifeEvent 触发需要检查 waterStress 和 careReadiness，资源不足时更可能延迟伴生生命。
14.2 绿洲规则
绿洲是生命机会集中的地貌，但空间并非无限。水和食物恢复较好，生命事件机会高，但过度聚集会提升空间压力和水源压力。
waterCap 高，foodProduction 高；但 spaceCapacity 中低。
温暖/照护型管家可能优先围绕水源建立生活核心。
保护型管家可能控制入口，避免资源被过度消耗。
社区发展快，但需要 ResourceAudit 检查水源消耗。
14.3 森林规则
森林资源丰富但路径复杂。木材多、阴影多，适合木屋、边界和隐蔽空间；但如果不维护，路径会被自然生长重新吞没。
woodStock 高，woodRegenRate 高；pathMaintenanceCost 高。
quietMaintainer 高的管家会保留更多自然边界。
structuredBuilder 高的管家会优先开辟直路与储物区。
森林里的建筑需要维护防潮和清路。
14.4 草地规则
草地适合初始 MVP，因为规则相对中性。但草地也不是空白画布，过度建设会造成 spacePressure 和 ecologyHealth 下降。
地面稳定中高，constructionCost 中低。
适合快速验证家园生成、道路、住所、储物、自然边界。
长期需要草地恢复和踩踏痕迹维护。
草地不能永远只有大面积绿色方块，必须有资源与生态状态。
15. 资源循环算法细化
资源循环不是每 tick 简单 +1，而是受地貌、天气、消耗、维护、建筑状态和事件影响。MVP 可以先简化，但字段与审计要按完整模型预留。
function runResourceCycle(input) {
  naturalRegen = biome.regenRates * weatherMultiplier * ecologyHealth;
  consumption = agentNeeds + constructionCosts + maintenanceCosts;
  eventDelta = activeEvents.reduce(delta);
  nextStock = clamp(prevStock + naturalRegen - consumption + eventDelta, 0, biome.resourceCaps);
  warnings = auditResourceLaw(prevStock, nextStock, biome, consumption, eventDelta);
  return { nextResourceState, resourceDiff, warnings };
}
16. 管家自主建设决策评分
管家不是随机建造，也不是玩家命令建造。它会根据人格、资源压力、维护压力、阶段目标和地貌约束计算每个建设意图的优先级。
intentScore = baseGoalWeight
  + personalityWeight(goal, butlerProfile)
  + resourcePressureWeight(goal, resourceState)
  + biomeSuitabilityWeight(goal, biomeState)
  + maintenancePressureWeight(goal, durabilityState)
  + worldPhaseWeight(goal, phase)
  - resourceCostRisk(goal, availableResources)
  - overcrowdingPenalty(spacePressure)
17. 社区与小镇的自主形成机制
社区不是玩家造出来的行政区，而是多个家园在资源互补、道路连接、互助事件和公共需求中逐渐形成的。小镇也不是城市建造玩法，而是长期世界运行后出现的公共设施网络。
