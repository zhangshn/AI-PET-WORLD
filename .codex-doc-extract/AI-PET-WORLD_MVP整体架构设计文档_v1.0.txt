1. 架构总览
架构目标是让世界内容、地图变化、正式视觉模型都来自规则和结构化数据，而不是来自前端组件手写。
2. 核心设计原则
世界事实先于画面。
规则生成先于渲染。
布局由 seed、人格、资源、事件和规则共同生成，不固定模板化。
FormalVisualModel 是正式视觉模型容器。
FormalWorldView 只读渲染，不生成模型。
Debug View 与 Formal World View 分离。
宠物后置，petState 必须可选。

6. 非固定布局架构
布局系统必须是确定性生成系统，不是固定模板系统。
必须验证：不同人格会导致道路、住所、资源区、边界和生命接触预留区的布局差异。
7. Formal Visual Model 架构
FormalVisualGenerator 不能生成世界事实。
FormalVisualGenerator 不能生成 placement。
FormalVisualGenerator 不能伪造宠物。
FormalWorldView 不能替代 FormalVisualGenerator。
8. 前端与路由边界
9. 宠物后置架构
WorldState.petState 必须可选。
宠物未接纳前，FormalVisualModel 不生成 pet actor。
宠物必须通过 LifeEvent + CompanionDecision + accept_companion 进入。
宠物事件文本不能让宠物说人话。

13. 验收门槛
世界对象能追溯到 HomeMapState / placements / MapDiff。
正式视觉能追溯到 FormalVisualModel。
不同人格和 seed 生成可观察不同布局。
FormalWorldView 不生成模型。
无宠物运行正常。
正式 /world 不显示 Debug 信息。
lint、tsc、build 全通过。
14. 最终结论
AI-PET-WORLD MVP 架构的核心是：人格驱动规则世界生成，生成内容进入结构化容器，再由 FormalVisualModel 进入正式主视觉。
后续开发只要严格遵守“先容器、先模型、后只读渲染”，就能避免固定布局和前端手写世界的问题。
