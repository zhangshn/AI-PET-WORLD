0. 文档控制与统一口径
本版文档把“复杂”作为产品优势处理：复杂不是堆概念，而是把生态规律、有限资源、人格差异、自动建设、关系事件和可审计状态变化合成一套可以落地的世界引擎。
1. 架构总览
MVP 架构的核心目标是：让世界事实、地图变化、建设行为、资源变化和正式视觉模型都来自可审计数据容器，而不是来自前端组件手写。
CreateWorldInput
-> WorldCreationRuntime
-> ButlerPersonality/Profile
-> InitialHomeGenerator
-> HomeMapState
-> WorldLoop Tick
-> ConstructionPlanner / ResourceCycle / LifeEventCandidate
-> MapDiff / EventLog / SafeApply
-> nextHomeMapState
-> VisualState / RenderableWorldSnapshot
-> FormalVisualModel
-> FormalWorldView

4. 非固定世界生成架构
初始世界生成必须从“固定区域模板”升级为“规则候选 + 约束求解 + seed/personality/resource 驱动”。Scene Recipe 可以定义候选关系，但不能固定所有中心点和最终布局。
WorldLayoutGenerationInput = { seed, personality, resources, biome, phase, candidateAreas, constraints }
PlacementEngine(layoutInput) -> PlacementProposal[]
PlacementRules.validate(proposals) -> accepted placements -> HomeMapState
5. World Loop 设计
World Loop 是长期运行入口。MVP 阶段可以通过手动 Tick 或 debug runner 触发，但架构必须为未来离线运行、周期运行和事件驱动运行保留接口。
6. 自主建设架构
建设系统必须支持从“整理区域”升级到“建造自己喜欢的房子”。MVP 可先从候选计划和 MapDiff 开始，但类型体系要预留房屋偏好、建筑风格和社区设施。
7. ResourceCycle 与 EcologyEngine
为避免世界像静态场景，MVP 后续应建立资源循环与生态引擎。哪怕初期实现简化，也必须在架构中明确资源来源、消耗、恢复和上限。
8. LifeEvent / CompanionDecision 架构
宠物/伴生体必须是 LifeEvent 后置链路。系统要允许“某些管家长期不接纳伴生体”作为合法结果。
WorldReadiness + ButlerRelationBias + ResourceState + SpaceCapacity + EventHistory
-> LifeEventCandidate[]
-> CompanionDecisionCandidate[]
-> optional accept_companion
-> PetPersonalityProfile + petState + FormalActorModel projection
9. Formal Visual Generation Layer
FormalVisualModel 是正式主视觉模型，但不能创造世界事实。它只能从 VisualState/RenderableWorldSnapshot 派生，用于隐藏工程细节，向玩家呈现可读的世界。

15. 数据流详细用例
15.1 创建草地初始家园
用户输入生命信息。
WorldCreationRuntime 生成 birthSignature/worldSeed。
PersonalityCore 输出管家建设倾向。
BiomeEngine 选定草地或初始中性地貌。
LayoutGenerator 根据 seed/personality/resources 生成候选布局。
PlacementEngine 生成 HomeMapState placements。
FormalVisualModel 派生主视觉。
15.2 管家自动升级住所
WorldLoop 读取当前 HomeMapState 和 ResourceState。
Maintenance/Comfort 发现临时住所不足。
管家人格 protective/warm/structured 影响意图分数。
ConstructionPlanner 生成 house upgrade 候选。
Executor 生成 add/update MapDiff。
SafeApply 检查资源和空间。
/world 刷新后看到住所形态变化。
15.3 资源不足导致建设延期
WorldLoop 发现 materialReadiness 不足。
ConstructionPlanner 生成 prepare_materials 或 wait plan。
SafeApply 拒绝直接建房 diff。
P-Phone 显示管家解释：资源不足，先整理储备区。
15.4 伴生生命机会被延后
LifeEvent 候选检测到 companion_opportunity_later。
CompanionDecision 读取资源、空间、管家关系倾向。
资源不足或保护倾向高时返回 wait_and_observe。
不生成宠物 actor，只生成日志和解释。

17. 持久化与离线运行边界
MVP 初期可以只做 memory preview / localStorage / dry-run，但必须设计成未来可接服务端。离线运行不是前端 setInterval 乱跑，而是根据上次保存时间计算可审计的补偿 tick。
