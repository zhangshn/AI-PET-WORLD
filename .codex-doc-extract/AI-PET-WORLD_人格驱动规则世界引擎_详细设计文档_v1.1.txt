AI-PET-WORLD 人格驱动规则世界引擎设计文档 v1.1
本版修订重点：补充“点、线、面组成图形”的基础生成逻辑，明确它早于 Point / Line / Polygon 工程协议。
1. 核心定义
AI-PET-WORLD 的世界不是一张预先画好的地图，也不是随机程序生成地图。

它的本质是：
玩家生命信息 → 管家人格 → 行为意图 → 世界规则验证 → 世界结构变化 → Renderer 绘制结果

因此，AI-PET-WORLD 的世界不是“自动随机成长”，而是：
人格驱动的规则世界。

世界规则决定“什么能发生”。
管家人格决定“想不想发生”。
生态环境决定“有没有必要发生”。
空间结构决定“在哪里发生”。
世界变化层决定“发生之后留下什么”。
2. 世界引擎总结构
AI-PET-WORLD 世界生成引擎分为五个核心层级：

1. 世界规则层 World Rule Layer
2. 世界空间层 Spatial Geometry Layer
3. 世界生态层 Ecology & Environment Layer
4. 行为意图层 Intent System Layer
5. 世界变化层 World Evolution Layer

其中：
- 世界规则层：最固定，属于自然法则。
- 世界空间层：相对稳定，但会随建设和生态变化。
- 世界生态层：持续变化。
- 行为意图层：由人格与世界状态共同决定。
- 世界变化层：真正把结果写入世界。
3. 世界规则层
世界规则层定义最基础的自然法则：

树必须生长在土地上。
鱼必须生活在水里。
房屋必须有地基。
地基必须建立在可承重地面上。
道路必须连接有效区域。
沙漠不能自然生成普通树木。

世界规则不负责画地图。
它只负责判断：
某个对象能不能出现。
某个行为能不能执行。
某个变化是否合法。
4. 世界空间层（重点修正版）
这里必须明确一个顺序：

第一步：图形生成基础 —— 点、线、面组成图形。
第二步：工程空间协议 —— Point、Line、Polygon、MultiPolygon。

也就是说，Point / Line / Polygon 不是最开始的思想本身，
而是“点、线、面组成图形”在工程中的抽象表达。

AI-PET-WORLD 的世界对象，不应先被理解成贴图。
而应先被理解成几何结构。
5. 点、线、面组成图形
点：位置、锚点、入口、生长点、支撑点。
线：连接、边界、道路、墙体、河流、结构梁。
面：土地、水域、森林、地基、屋顶、活动区、影响区。

点可以连接成线。
线可以围合成面。
面可以形成实体的占地、碰撞、支撑和影响范围。

因此：
世界不是先画一张图片。
世界是先生成几何结构。
Renderer 再根据几何结构把它画出来。
6. 示例：树如何组成
树不是 tree.png。

树应该被拆解为：

点：树干中心、生长点。
线：树干方向、主要枝干结构。
面：树冠范围、根系范围、树荫范围、生态影响区。

规则判断时：
- 根系是否落在土地上
- 树冠是否与建筑冲突
- 阴影是否影响附近生态

Renderer 再根据这些结构绘制树。
7. 示例：房屋如何组成
房屋不是 house.png。

房屋应该被拆解为：

点：入口点、支撑点、功能点。
线：墙线、梁线、屋脊线。
面：地基面、屋顶面、室内面、碰撞面。

当管家产生“建房”意图时：

生成地基面
→ 检查承重
→ 推导墙线
→ 推导屋顶
→ 生成建筑阶段
→ Renderer 绘制
8. 工程空间协议
在工程实现中，点、线、面会被抽象为：

Point：实体锚点、入口、中心位置。
Line：道路、河流、围栏、墙体、移动路径。
Polygon：土地、水域、森林、建筑地基。
MultiPolygon：复杂不规则区域。

这一步属于工程化协议，而不是最初的世界思想。
9. 世界生态层
生态层包含：

地形：土地、水域、森林、沙地。
环境：湿度、温度、肥力、坡度。
物种：植物、动物、宠物。
物质：木材、水、石头、食物。

生态会互相影响：

雨水增加
→ 土地湿度上升
→ 草地扩张

干旱
→ 水域缩小
→ 鱼减少
10. 行为意图层
世界不会自动成长。

世界是否变化，取决于：

管家人格
宠物状态
天气季节
资源物质
生态环境
当前世界结构

有些人格会持续建设。
有些人格只会维护。
有些人格长期停滞。
有些人格会破坏和重构。
11. 世界变化层
完整流程：

Intent
→ Planner
→ Rule Validator
→ World Diff
→ World State

世界变化包括：

GeometryDiff
EntityDiff
EcologyDiff
ConstructionDiff
StateDiff

世界变化不是时间驱动。
而是人格 + 状态 + 规则共同驱动。
12. Renderer 职责边界
Renderer 不创造世界。

Renderer 只读取 WorldState 并绘制结果。

Renderer 不能：
- 决定世界生成
- 决定建筑是否出现
- 绕过规则直接摆素材
- 把世界做成一张背景图

Renderer 应该：
点 → 画实体锚点
线 → 画道路 / 河流 / 墙体
面 → 画地块 / 湖泊 / 森林 / 建筑
13. MVP 当前正确顺序
当前阶段不应该继续围绕贴图 Renderer。

正确顺序：

1. 固定世界规则协议
2. 固定点线面图形生成逻辑
3. 固定 Point / Line / Polygon 协议
4. 固定 footprint / collision / influence 协议
5. 固定 Intent → Plan → Validate → Diff → WorldState
6. 最后再做 Renderer
14. 最终定义
AI-PET-WORLD 的第一核心：命理人格系统。

AI-PET-WORLD 的第二核心：人格驱动规则世界模拟引擎。

最终产品定义：

AI-PET-WORLD 是一个由人格驱动、规则约束、生态反馈、长期演化的 AI 生命世界。
