1. v1.5 修正说明与逻辑自检
v1.5 不推翻 v1.4，而是在 v1.4 已确认的 Formal Visual Generation Layer 基础上，补齐“非固定布局”和“生成内容容器”的硬性规则。
逻辑自检结果：本计划可以继续执行。理由是：世界事实、视觉模型和渲染职责已经分层；布局差异由 seed、人格、资源、状态、建设意图和规则共同驱动；FormalWorldView 不承担生成职责。
2. 产品一句话定义
AI-PET-WORLD 是一个以玩家真实生命信息为源头，由命理人格算法生成 AI 管家底层人格，再由管家自主意识、世界规则、资源循环、长期记忆、世界生成层、Formal Visual Generation Layer 与 Renderer 共同驱动家园成长的 AI 生命世界。
玩家不是直接操作者，而是世界源头、观察者和陪伴者。管家是玩家生命信息映射出的第一生命。宠物不是开局默认资产，而是世界运行后可能被管家接触、判断、接纳并建立关系的独立生命。
3. MVP 总目标
玩家输入真实生命信息后，系统生成管家的源头人格、管理风格、生活倾向、建设倾向、关系倾向和视觉倾向。
管家作为第一生命进入世界，世界初始状态可以没有宠物，但必须可以独立运行。
世界能生成一个可见、可保存、可继续变化的初始像素家园。
布局不能是固定模板，必须由 worldSeed、管家人格、资源、事件、建设意图和空间规则共同生成。
管家行为结果不是直接改前端页面，而是生成 ConstructionPlan、MapDiff、placements、eventLogs 等结构化世界变化数据。
FormalVisualGenerator 从已存在世界事实中生成 FormalVisualModel；FormalWorldView 只读 FormalVisualModel。
宠物作为后续生命关系事件出现，只有当接纳发生后，宠物系统才进入主运行闭环。
MVP UI 可以低保真，但不能由前端手写世界对象、固定布局或角色模型。
4. 核心架构
v1.5 使用“横向八层 + 视觉模型生成横切层 + 生成内容容器层 + 纵向生命线层”的架构。
5. 业务主线：管家先行，宠物后置
v1.5 继续保持管家先行、宠物后置。玩家输入真实生命信息后，系统生成映射玩家生命信息的 AI 管家。管家作为第一生命进入世界，先面对空地、资源、天气、时间和基础生活需求。
宠物不是系统强制送给玩家的开局对象，而是在后续世界运行中出现的生命关系事件。只有 accept_companion 发生后，宠物才正式进入玩家家园世界。
6. 命理人格核心
personality-core 不因世界生成层、Formal Visual Model 或宠物后置主线而重写。
正式 UI 不显示紫微斗数术语，只显示人格结果、行为倾向、管家解释和世界变化。
PersonalityProfile 必须输出 constructionStyle、lifeRhythmBias、companionDecisionBias、relationBias 与 visualTendency。
visualTendency 可以影响 FormalVisualModel 的 styleToken、mood、atmosphere，但不能让 UI 直接生成世界事实。
7. 世界时间、资源与建设规则
真实命理时间用于人格生成，不加速。
AI 世界时间用于昼夜、资源、天气、管家生活、建设、宠物作息，可加速。
建设不能凭空发生，必须有土地、空间、材料、时间和管家意图。
玩家不直接点击建造，家园变化来自管家判断、资源状态、天气、时间、事件和人格倾向。
8. 世界生成与非固定布局
世界生成不是固定模板，也不是无约束随机。它是 seed + 人格 + 规则 + 状态共同驱动的确定性程序化生成。
验收要求：同一玩家 seed 和同一状态下布局稳定；不同玩家、不同管家人格、不同资源和事件状态下布局必须有可观察差异。
9. 自动生成内容容器
10. Formal Visual Generation Layer
Formal Visual Generation Layer 是正式主视觉之前的模型生成层。它从 VisualState / RenderableWorldSnapshot 派生 FormalVisualModel。
11. Renderer / FormalWorldView 边界
Renderer Core 只读 VisualState / RenderableWorldSnapshot，Debug View 可以显示 diagnostics。
FormalWorldView 只读 FormalVisualModel；过渡期最多只读 RenderableWorldSnapshot，但不能生成正式视觉模型。
FormalWorldView 不能定义 FormalWorldVisualItem / FormalActorVisualItem。
FormalWorldView 不能根据 UI 状态伪造宠物、管家或世界对象。
12. MVP UI 边界
MVP 阶段这种低保真温暖自然 UI 可以作为方向，但实现方式必须由规则和模型驱动。
13. 像素资产管线
像素资产是生成系统可调用的表现资源，不是世界事实来源。树必须先是世界实体、placement、几何结构、生态影响区或资源状态的一部分；tree.png 只能在渲染阶段作为表现资源被调用。

18. Codex 开发纪律
不允许 AI 自由设计 /world 地图。
不允许固定布局模板作为正式主路径。
不允许在 FormalWorldView 内生成 FormalWorldVisualItem / FormalActorVisualItem。
正式视觉模型必须来自 src/world/formal-visual-model/。
每轮必须说明当前做什么、不做什么、改哪些文件、不改哪些文件、完成后如何验证。
如果涉及视觉呈现，必须额外确认：是否固定布局、是否组件生成模型、是否只读 FormalVisualModel。
19. MVP v1.5 验收标准
玩家打开世界后能看出这是像素生命世界，不是文字游戏或坐标测试图。
同一 seed 与状态下布局稳定，不同人格、资源、事件状态下布局有可观察差异。
FormalVisualModel 从 VisualState / RenderableWorldSnapshot 派生。
FormalWorldView 不生成世界对象、不生成 actor、不生成 placement、不生成正式视觉模型。
无宠物运行不报错、不空转。
宠物只能通过生命关系事件和管家接纳进入主循环。
正式 /world 不显示白色网格、坐标标签、raw tags、source diagnostics。
lint、tsc、build 全通过。

21. 最终结论
MVP v1.5 的核心不是做一张好看的固定图，而是跑通一个完整闭环：玩家输入真实生命信息 -> 生成管家人格 -> 生成初始家园 -> 生成 FormalVisualModel -> FormalWorldView 只读呈现 -> 管家独立生活与建设 -> 生命事件出现 -> 管家自主决定是否接纳宠物 -> 玩家看到家园与关系逐步变化。
MVP 阶段 UI 可以低保真，但必须由自动生成容器和规则驱动。固定布局、前端手写模型、组件内生成世界内容都不符合计划。
