# AI-PET-WORLD MVP 核心需求锁定 v1.1

## 1. 一句话定义

AI-PET-WORLD 是一个以用户真实生命信息为源头，以紫微斗数为主算法、八字为出生时间缺失时的辅助补全机制，映射出管家人格、宠物匹配、家园风格，并由 AI 管家和 AI 宠物自主运行的像素生命世界。

## 2. 产品不是普通像素游戏

AI-PET-WORLD 不是普通养宠游戏，不是普通经营建造游戏，不是玩家点击建房子的游戏，不是随机宠物系统，也不是普通像素地图编辑器。

紫微斗数不是装饰功能，而是第一核心。八字不是并列核心，只在出生时间缺失时辅助补全。

它是一套 AI 运作方式：

```txt
真实出生信息
↓
紫微斗数主算法
↓
出生时间缺失时，八字辅助补全
↓
人格与阶段解析
↓
视觉 DNA
↓
管家初始形象
↓
宠物匹配
↓
家园风格
↓
AI 管家自主建设
↓
AI 宠物自主生活
↓
世界持续演化
```

## 3. MVP 核心需求表

| 序号 | 核心需求 |
| --- | --- |
| 1 | 紫微斗数是产品第一核心，不是装饰功能。 |
| 2 | 八字不是并列核心，只是出生时间缺失时的辅助补全机制。 |
| 3 | 用户真实出生信息生成管家源头人格 / 初始形象。 |
| 4 | 宠物不是随机宠物，而是根据用户紫微人格倾向匹配。 |
| 5 | 宠物性格用真实抵达时间映射，不用游戏加速时间。 |
| 6 | UI 世界不是普通像素地图，而是紫微驱动生成的世界。 |
| 7 | 世界资源像真实地球，有生成、消耗、恢复、循环。 |
| 8 | 世界显示 24 小时制，命理映射走真实时间。 |
| 9 | 管家自主建设家园，玩家不直接点击建造。 |
| 10 | 管家根据紫微人格、资源、宠物需求建设房子 / 花园 / 照护点。 |
| 11 | 现有小组件是 Primitive 语义零件，不是最终视觉。 |
| 12 | 最终视觉应走 Sprite / Prefab / Scene，而不是色块拼接。 |
| 13 | 房屋要有阶段：空地 → 照护点 → 临时住所 → 基础小屋 → 稳定家园。 |
| 14 | 临时领养中心可以作为 MVP 临时设施，未来小镇有大型领养中心。 |
| 15 | 社区规则本阶段不定义，未来由 AI 自发发起，人类不参与。 |
| 16 | 每次继续开发前都必须打印此 MVP 核心表。 |

## 4. 紫微斗数与八字的主辅关系

### 紫微斗数

- 是主核心。
- 用于完整出生时间下的命盘计算。
- 用于管家源头人格。
- 用于宠物匹配倾向。
- 用于家园风格倾向。
- 用于视觉 DNA。
- 用于用户当前阶段解析。

### 八字

- 不是并列核心。
- 不是主要卖点。
- 不是优先算法。
- 只在用户没有出生时间、出生时间缺失或出生时间不确定时作为辅助补全。
- 用于补足基础人格倾向、五行气质、初步视觉方向和基础风格判断。

## 5. MVP 阶段暂不做

- 不做正式社区规则。
- 不做玩家手动建设社区。
- 不做正式素材替换。
- 不接复杂 Pixi。
- 不做商城。
- 不做多玩家经济。
- 不做正式城市系统。
- 不做大型小镇系统。
- 不做真实图片素材管线。
- 不把八字做成并列核心系统。

## 6. MVP 阶段必须做

- 紫微斗数主算法。
- 出生时间缺失时的八字辅助补全。
- 真实时间命理映射。
- 管家人格。
- 宠物匹配规则。
- 视觉 DNA。
- 像素原型规范。
- 家园阶段。
- 资源规则。
- 管家自主建设逻辑的规则定义。
- 开发测试页用于查看 Primitive / Sprite / Prefab / Scene。
