## Current V2.6 Alignment

The historical MVP route used an earlier formal visual validation surface and MVP read-only panels. That route is no longer the current formal `/world` primary experience.

Current formal `/world` route:

```txt
WorldRuntimeSaveRecord + HomeMapState + SpaceGrid + TraceField + ButlerState
-> WorldViewModel
-> PixelWorldView
-> Tile / Trace / Object / Sprite / Atmosphere Layer
```

Historical formal visual components, procedural renderer previews, MVP panels, audit cards, dry-run reports, and manual controls must stay in `/world-debug` or historical validation contexts.

## Historical MVP Meaning

This phase proved that several MVP subsystems could be connected for development verification:

- world creation inputs
- butler profile mapping
- initial HomeMapState generation
- construction and SafeApply experiments
- dry-run persistence checks
- P-Phone style summaries
- adoption precheck as a later candidate concept
- read-only MVP presentation panels

These historical results do not mean the current formal player world should show debug cards or old renderer surfaces.

## Current Red Lines

- Formal `/world` must be PixelWorldView-first.
- Formal `/world` must not use old formal visual validation components as its primary surface.
- Formal `/world` must not use procedural renderer previews as its primary surface.
- Formal `/world` must not display audit trails, dry-run reports, or engineering field tables as the main experience.
- UI must not generate world facts.
- Pet must not be generated by default.
