# 项目文档规则

更新时间：2026-07-11 12:32:00 +08:00

状态：active-governance / 已生效

不允许自由发挥；除非发现错误导致无法继续，必须先停下来询问项目所有者。

## 1. 固定原则

| 规则 | 要求 |
|---|---|
| 新文档必须带强制句 | 从本文件之后新增或更新的项目文档，必须包含：“不允许自由发挥；除非发现错误导致无法继续，必须先停下来询问项目所有者。” |
| 不用临时文档替代正式文档 | 新增页面、训练流程、数据字典、审核规则前，必须先放到对应正式文档目录 |
| 不随意改页面 | 页面结构、入口、命名、样式、数据显示范围，必须先有文档锁定规格 |
| 不随意改训练路线 | 训练数据、模型版本、输出目录、审核门槛发生变化前，必须先说明原因和影响 |
| 发现阻断先停 | 如果继续执行会造成版本混乱、数据覆盖、记录缺失或标准不清，必须先停下来询问项目所有者 |
| 唯一当前入口 | 只有 `docs/game-world-generation/CURRENT_EXECUTION_GUIDE_20260710.md` 可以决定当前世界地图下一步 |
| 旧文档不保留 | 被正式文档替代的旧计划、旧进度、阶段报告和重复说明必须删除，不建立历史文档目录 |
| 运行证据不等于文档 | 训练图、失败图、审核记录、程序事件和模型产物继续由程序保存在 `data/` 或 `.runtime/`，不得因为清理文档而删除 |
| 更新时间写完整 | 所有新增或更新文档必须写 `YYYY-MM-DD HH:mm:ss +08:00` |
| 下级规格数量锁定 | 当前地图架构只保留视觉实现、训练数据来源、审核自动化与存储 3 份下级规格；禁止重建阶段性文档树 |
| 字典按需读取 | 智能体不得默认批量读取视觉字典条目，只读 README、当前导出 JSON 和任务明确涉及条目 |

## 2. 文档分类

| 类型 | 位置 | 要求 |
|---|---|---|
| 项目总规则 | `docs/` | 只能写长期有效规则 |
| 页面锁定规格 | `docs/<page-or-module>/` | 必须写清页面职责、数据来源、禁止事项和验收标准 |
| 数据字典 | `docs/world-visual-data-dictionary/` | 只定义小模型、程序审核、人工审核共用标准 |
| 当前完整世界架构 | `docs/game-world-generation/` | 当前世界地图架构、验收和执行指南 |
| 世界视觉数据字典 | `docs/world-visual-data-dictionary/` | 当前视觉事实和训练标签参考，不直接决定下一步 |
| 管家人格数据子系统 | `docs/ziwei/` | 技术与文档独立维护，不参与当前世界地图执行顺序；其结构化结果必须通过人格映射契约服务 AI 管家核心业务 |

文档分类和优先级以 `docs/DOCUMENT_AUTHORITY_INDEX.md` 为准。

## 3. 修改流程

| 步骤 | 要求 |
|---:|---|
| 1 | 先确认是否已有锁定规格 |
| 2 | 如果没有，先写规格，不直接改页面或训练程序 |
| 3 | 如果规格和实际代码冲突，先停下来说明冲突 |
| 4 | 得到项目所有者明确命令后再改 |
| 5 | 修改后必须打印进度表和计划表 |

## 4. 删除与合并规则

1. 正式规则已经进入当前权威文档后，旧计划、旧阶段表和重复说明立即删除。
2. 禁止新增 `history`、`archive-docs`、`old-docs` 等旧文档保存目录。
3. 文档删除前必须检查程序、页面和其他正式文档引用；删除后必须同步修复。
4. 数据字典的分层条目属于机器可导出的正式数据定义，不按普通阶段文档处理。
5. `.runtime` 和 `data` 中的自动训练证据不属于本规则的删除范围。
6. 提案内容只能合并进现有正式规格，禁止把聊天提案原文保存为新的平行计划。
