# AI-PET-WORLD｜版权、授权与学习数据治理规范

> 本文档用于约束 AI-PET-WORLD 在代码、素材、AI 辅助生成、学习模块、用户反馈和上线发布中的版权与授权边界。
>
> 本文档不是法律意见。正式商业发布、Steam 上架、融资、合作、发行或大规模用户上线前，应由专业律师进行最终审核。

---

## 1. 文档目的

AI-PET-WORLD 是一个长期演化的 AI 自主世界项目，包含：

- AI 辅助代码生成
- 程序化像素绘制
- 像素素材 recipe
- 未来 AI 概念图 / 宣传图 / 头像 / 插画
- 本地反馈学习
- 用户通过 P-Phone 反馈形成的个人世界偏好
- 未来可能出现的聚合学习和视觉评审

因此项目必须从早期开始建立版权、授权、数据使用和学习边界，避免后期出现不可追溯、不可上线、不可商用的问题。

---

## 2. 总原则

### 2.1 AI 辅助不等于无版权风险

AI 辅助写代码、生成文案、生成图像或帮助设计规则，并不自动意味着内容一定安全，也不自动意味着内容一定侵权。

项目必须管理的是：

- 来源是否可追溯
- 是否复制第三方代码或素材
- 是否使用了不兼容开源许可证
- 是否使用了未授权图片、音频、字体或模型数据
- 是否过度模仿已有商业游戏或 IP
- 是否能证明核心架构、规则和素材来自本项目自有设计

### 2.2 不以未授权数据作为学习来源

MVP 阶段禁止建立互联网抓取式学习系统。

禁止：

- 自动爬取互联网图片作为训练数据
- 自动抓取其他游戏截图作为训练数据
- 使用未授权像素素材训练生成器
- 使用第三方商业游戏素材作为正式素材来源
- 使用不明确授权的字体、音乐、音效、图标和 UI 资源

允许：

- 使用本项目程序化生成的候选结果
- 使用创作者在 Debug 中给出的反馈
- 使用用户通过 P-Phone 对自己世界给出的反馈
- 使用 Validator / smoke / runtime 产生的结构化检查结果
- 使用人工确认后的项目内 golden sample

### 2.3 学习结果不能直接改写正式世界

学习模块只能生成建议、偏好、权重、候选和草稿。

任何学习结果进入正式规则前，必须经过：

```txt
Feedback
→ Learning Draft
→ Validator
→ Debug Review
→ Promotion Gate
→ Recipe Version
→ Formal Usage
```

禁止学习结果绕过世界规则、版权规则、人工确认和版本治理直接进入正式 `/world`。

## 3. AI 辅助代码使用规范

### 3.1 允许范围

允许使用 AI 辅助：

- 生成本项目自有业务逻辑代码
- 重构本项目已有代码
- 编写测试、smoke、文档和类型定义
- 根据本项目架构文档实现模块
- 解释错误日志并提出修复方案

### 3.2 禁止范围

禁止要求 AI：

- 照抄某个开源项目实现
- 复刻某个商业游戏代码结构
- 生成“和某某项目一模一样”的代码
- 粘贴未知来源的大段代码进入项目
- 将不明许可证代码合并到项目

### 3.3 代码审查要求

AI 生成代码进入项目前，至少检查：

- 是否符合本项目架构和命名
- 是否包含未知来源版权声明
- 是否包含外部项目特有标识
- 是否引入不明依赖
- 是否绕过现有 runtime / debug / formal 边界
- 是否能通过 lint / typecheck / build / smoke

## 4. 开源依赖治理

### 4.1 依赖接入前必须确认许可证

新增 npm 包、字体包、图标包、图形库、音频库或任何第三方库前，必须确认：

```txt
来源
许可证
是否允许商用
是否需要署名
是否需要保留 notice
是否与闭源 / Steam 发布兼容
```

### 4.2 许可证风险等级

低风险优先：

- MIT
- Apache-2.0
- BSD
- ISC

谨慎使用：

- LGPL
- MPL
- Creative Commons 系列

默认禁止或必须人工法律审核：

- GPL
- AGPL
- 未声明许可证
- 仅限个人使用
- 仅限非商业使用
- 来源不明资源

### 4.3 上线前必须做依赖 license audit

正式上线前必须输出：

- dependency license list
- third-party notice
- 明确不可商用依赖清理结果
- 字体 / 图标 / 音频 / 图片授权记录

## 5. 视觉素材治理

### 5.1 正式素材优先来源

正式视觉资产优先来自：

- 本项目程序化像素 recipe
- 本项目自定义 palette
- 本项目自定义 pixel primitive library
- 本项目生成并人工确认的 golden sample
- 明确授权的原创素材
- 明确商用许可的第三方素材

### 5.2 禁止项

禁止：

- 复制商业游戏像素素材
- 复制知名 IP 角色、宠物、建筑或 UI
- 使用未授权图标、字体、图片、音乐、音效
- 直接把 AI 参考图当作正式素材而不经过授权确认
- 以“像素版某知名游戏 / 某知名角色”为目标生成正式素材

### 5.3 AI 概念图的定位

AI 概念图可以用于：

- 风格探索
- 色板参考
- 轮廓参考
- 宣传方向草稿
- 角色气质参考

但不能自动成为正式游戏素材。

AI 概念图进入正式素材前，必须经过：

```txt
来源记录
人工审核
相似性检查
授权确认
项目内重构或程序化转译
```

## 6. 像素绘制与 recipe 治理

### 6.1 程序化像素绘制优先

AI-PET-WORLD 的正式主世界视觉应优先使用：

```txt
Pixel Primitive
→ Pixel Shape
→ Pixel Part
→ Pixel Object Recipe
→ Scene Composition
→ PixelWorldView
```

原因：

- 可控
- 可复现
- 可解释
- 可接世界状态
- 可接管家 / 宠物 / 痕迹 / 时间线
- 版权边界更清晰

### 6.2 recipe 必须可追溯

每个正式 recipe 必须记录：

- recipeId
- recipeVersion
- 使用的 primitives
- 使用的 shapes
- 使用的 parts
- 使用的 palette
- 是否经过 validator
- 是否经过 promotion gate

### 6.3 禁止直接复制外部像素图

外部图像只能作为人工观察参考，不能直接拆成像素块进入正式 recipe。

## 7. 学习模块数据边界

### 7.1 MVP 学习来源

MVP 阶段学习模块允许使用：

- 创作者在 Debug 页面中的反馈
- 系统自己生成的候选结果
- Validator 结构化检查结果
- smoke / runtime 结构化结果
- 用户通过 P-Phone 对个人世界的反馈

### 7.2 MVP 禁止学习来源

MVP 阶段禁止使用：

- 互联网抓取图片
- 未授权游戏截图
- 未授权素材库
- 未授权字体 / 音频 / 图片
- 用户上传图片作为全局训练数据
- 第三方平台内容作为训练数据

### 7.3 用户反馈使用边界

用户通过 P-Phone 反馈后，默认只允许影响：

- 用户自己的世界偏好
- 当前世界的视觉偏好权重
- 管家的解释记忆
- 后续候选生成倾向

用户反馈默认不进入全局学习。

全局学习必须满足：

- 明确授权
- 匿名化
- 聚合统计
- 达到统计阈值
- 人工审核
- 可回滚

## 8. P-Phone 反馈治理

P-Phone 是用户与管家关系终端，不是调参面板。

用户可以说：

- “这里有点乱”
- “我喜欢这个小花园”
- “树太多了”
- “管家看起来有点僵硬”
- “这里感觉太冷清”

系统应转译为结构化反馈，例如：

```txt
visual_density_too_high
prefer_warmer_palette
tree_density_too_high
butler_pose_too_stiff
prefer_more_life_signals
```

禁止：

- 用户反馈直接删除世界事实
- 用户反馈绕过管家和世界规则
- 用户反馈直接改写全局 recipe
- 用户反馈直接训练全局模型

---

## 9. Promotion Gate 晋升规则

学习结果、候选素材、recipe 变体进入正式使用前，必须经过 Promotion Gate。

Promotion Gate 至少检查：

- 是否来源可追溯
- 是否无版权风险
- 是否通过 validator
- 是否符合正式 /world 边界
- 是否不含 Debug 依赖
- 是否不依赖未授权数据
- 是否能通过 smoke
- 是否有版本记录
- 是否可回滚

晋升等级：

```txt
debug_only
local_world_preference
global_draft
global_candidate
formal_global
```

## 10. 本地存储阶段治理

当前未接入数据库时，学习样本可暂存在：

```txt
.runtime/learning/feedback-samples.json
.runtime/learning/recipe-weight-drafts.json
.runtime/learning/pixel-visual-preferences.json
.runtime/learning/promotion-candidates.json
```

要求：

- 不提交用户隐私数据
- 不提交敏感个人数据
- 不提交第三方素材原图
- 不提交未授权训练数据
- 开发期可使用本地 JSON
- 上线多用户阶段必须迁移到数据库或合规存储服务

## 11. 上线前版权检查清单

上线前必须检查：

- [ ] 所有 npm 依赖许可证
- [ ] 所有字体授权
- [ ] 所有图标授权
- [ ] 所有音乐授权
- [ ] 所有音效授权
- [ ] 所有图片 / 插画 / 宣传图来源
- [ ] AI 生成素材是否有来源记录
- [ ] 是否存在模仿知名 IP 的风险
- [ ] 是否存在未授权素材
- [ ] 是否存在 GPL / AGPL 等高风险依赖
- [ ] 是否生成 third-party notices
- [ ] 是否有 LICENSE / NOTICE 文件
- [ ] 学习模块是否禁止未授权互联网训练
- [ ] 用户反馈是否只影响允许范围
- [ ] Promotion Gate 是否阻止未审核结果进入正式世界

---

## 12. 当前阶段结论

AI-PET-WORLD 当前阶段应采用：

```txt
自有规则
+ 程序化像素生成
+ 本地反馈学习
+ 用户 P-Phone 个人偏好反馈
+ Promotion Gate
+ 上线前 license audit
```

暂不采用：

```txt
互联网图片抓取
未授权素材训练
自动全局学习
直接 AI 生图进入正式主世界
未审核用户反馈改写世界
```

版权治理不是后期补丁，而是 AI-PET-WORLD 长期可上线、可商用、可扩展的基础工程。
