# 流动水体连接与全历史去重规范

更新时间：2026-08-03 09:23:45 +08:00

状态：active-flowing-water-contract

Codex等外部执行智能体不得超出当前用户任务范围；本地程序在生效业务、安全和机器合同内自主运行，不从聊天或本句推导逐步Owner审批。

正式机器合同：`data/ai-painter/system-governance/thailand-rebuild64-flowing-water-connectivity-and-all-history-novelty-contract-v1.json`

## 1. 业务目标

训练原图同时服务本地 AI 训练、未来游戏画面与动态世界。定义为流动水体的河流或溪流必须加入大世界 HydrologyGraph，具有真实上游、下游、流向、海拔关系和相邻区域连接；水体不能只是画面内部的装饰形状。

## 2. 水文连接

- 外部水口数量、方向和类型由当前区域 WorldFacts 决定，不得统一固定为北入南出。
- 每个跨区域水口必须绑定相邻区域和成对 EdgePort，并在 HydrologyGraph 中形成有向连通关系。
- `terrain_water` 权威掩码与最终 RGB 水面必须实际接触约定边界；只在内部结束、缺少入口或出口、接触未约定边界均直接失败。
- 支流、分汊、汇流、回水区、湿地和岸线必须与正式主水系关系一致；随机水坑不能代替水文连通。
- 封闭池塘、内部湿地和无水区域按自身事实表达，不得强制添加外部水口。

## 3. 全历史唯一性

- 同一数据包先执行全部样本对条件比较，再调用生成算力。
- 比较道路、水轴、岸线、支流、分汊、汇流、弯折序列、道路—水体关系和完整骨架。
- 与全部成功、待审、机器失败和 Owner 拒绝历史比较，不能只比较同槽位或同景观。
- 平移、缩放、镜像、旋转、换方向、换宽度、换道路或轻微变形不能把同一水体模板变成新样本。
- RGB 生成后执行位置与尺度归一化的水体和岸线形状比较，防止生成器把不同条件压缩成同一视觉模板。

## 4. 真实来源与匿名坐标

MVP 水文支撑来自正式 Sakaerat / Wang Nam Khiao 泰国测量包。不同地图使用与自身区域身份绑定的测量窗口；真实精确坐标不得复制为游戏导航几何。

匿名投影可以改变游戏坐标，但河网类型、坡向、汇流和排水关系必须由当前测量窗口支撑，并保存来源、版本、许可、哈希和派生说明。未来区域必须使用自身来源包，不能复用泰国水文事实。

## 5. 验收与授权边界

条件包通过只证明水文事实、连接和生成前唯一性合格，不等于 RGB、训练或 Runtime 通过。生成后仍须执行条件响应、全历史 RGB、岸线、道路避水和完整世界审核。

具体样本、测量窗口、比较数量、失败结果和哈希由机器证据保存。本文不授权 RGB 生成、训练、验证、RuntimeFrame 或 `/world`。
