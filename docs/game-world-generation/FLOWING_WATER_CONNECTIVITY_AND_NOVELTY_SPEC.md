# 流动水体连接与全历史去重规范

更新时间：2026-08-01 18:35:00 +08:00

状态：active-architecture / 适用于 `thailand-rebuild64-20260731` 及后续完整世界训练原图

正式机器合同：`data/ai-painter/system-governance/thailand-rebuild64-flowing-water-connectivity-and-all-history-novelty-contract-v1.json`

## 1. 业务目标

训练原图同时是本地 AI 的正向训练数据、未来游戏静态世界画面和动态世界底图。水体不能只是画面内部的装饰形状；凡定义为流动河道的地图，都必须能加入大世界水文图，并保留明确的上游、下游和相邻区域连接。

## 2. 水文硬合同

- 每张流动水体地图必须有且仅有两个正式外部水口：北侧 `upstream_inlet` 和南侧 `downstream_outlet`。
- 两个水口必须各自绑定相邻区域及成对 EdgePort；HydrologyGraph 必须给出从上游到下游的有向边。
- `terrain_water` 权威掩码和最终 RGB 水面都必须实际接触两个约定边界；只在画面内部结束、只有入口、只有出口或接触未约定边界均直接失败。
- 水岸线、湿地、回水区和支流必须连接到正式主水系，不允许用随机水坑代替水文连通。

## 3. 唯一性硬合同

- 当前 64 组先进行 2016 对条件包比较；道路、水轴、岸线、分支侧、弯折序列、支流数量、道路—水体关系及完整骨架任一硬重复均不得出图。
- 同一批次的两个条件包必须在任何 RGB 生成前互相比较，不能因为“都还没有图片”绕过门禁。
- 还必须与全部历史成功和失败记录比较；换槽位名、换标签、平移、缩放、镜像、旋转或只改道路不能把同一水体框架变成新样本。
- RGB 生成后增加裁切与尺度归一化水体形状比较，避免相同河道通过位置变化逃逸。

## 4. 真实数据与匿名游戏坐标

所有地形、水文支撑和生态事实仍来自正式 Sakaerat / Wang Nam Khiao 泰国测量包。不同地图使用不同测量窗口；真实精确坐标不得复制进游戏。匿名投影可以改变游戏坐标，但形态选择必须由测量窗口的八段 DEM/D8 支撑、坡度、地势和排水事实驱动，并保存来源、版本、哈希和派生说明。

## 5. 当前修复结果

- 旧 `slot-190 v3` 与 `slot-194 v3` 已保留原文件并重新判定为 `rejected`，不得作为正向训练数据。
- `slot-190` 新条件使用 `sakaerat-measurement-window-r05-c09-v3`，采用实测驱动的对岸进出投影、源头支流汇入主河结构。
- `slot-194` 新条件使用 `sakaerat-measurement-window-r10-c02-v3`，采用主河分汊—回归结构。
- 两个新条件包均具有北侧进水口和南侧出水口；当前 64 组 2016 对比较硬失败为 0，全历史预生成比较命中为 0。
- 本规范与条件包通过不等于生成 RGB，也不授权 GPU、RuntimeFrame 或 `/world`。
