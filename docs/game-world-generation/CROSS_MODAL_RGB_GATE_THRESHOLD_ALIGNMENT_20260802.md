# 条件图与 RGB 水体构图门禁阈值对齐

更新时间：2026-08-24 09:48:00 +08:00

状态：active-cross-modal-threshold-contract

不允许自由发挥；除非发现错误导致无法继续，必须先停下来询问项目所有者。

## 1. 目的

本规则防止条件数据互不重复，但生成 RGB 又坍缩成历史水体骨架。生成前条件审计和生成后 RGB 审计必须使用相同的尺度、归一化、变换和阈值合同。

## 2. 正式阈值合同

- 候选条件只与历史 RGB 做审核比较，历史 RGB 不得成为生成参考。
- 比较覆盖全部历史完整地图，不得只比较同槽位、同景观或活动数据包。
- 水体掩码执行位置与尺度归一化；`normalizedWaterShapeIntersection` 上限为 `0.45`。
- 生成前条件门禁与生成后 RGB 门禁共用 `0.45`，不得发生阶段间阈值漂移。
- 主河、支流、分汊、汇流、回水汊、岸线、外部水口和道路—水体关系共同构成完整签名，不能只比较主河中心线。
- 道路与水文都从当前测量窗口和当前区域连接实例派生，禁止复用其他样本模板。
- 任一门禁失败时保留图片与证据并进入失败记录；不得无限自动重试、降低阈值或伪造机器通过。

## 3. 阈值变更治理

阈值变更属于审核合同变更，必须：

1. 说明变更原因、影响范围和预期风险；
2. 建立独立能力版本，不得在当前失败运行内修改；
3. 对历史通过、历史失败和已知跨模态坍缩样本执行回归；
4. 生成新合同版本，不覆盖旧合同；
5. 保存代码、配置、阈值和回归证据哈希。

## 4. 记录边界

具体测量窗口、样本版本、比较数量、相似度、审核决定和内部票据消费属于运行证据，只保存到 `data/`、`.runtime/`和 SQLite。本文不保存个案结果，也不表示实现、训练、验证、RuntimeFrame 或世界运行已经发生。
