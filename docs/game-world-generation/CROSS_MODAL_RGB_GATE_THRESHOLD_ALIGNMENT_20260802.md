## 1. 目的

本规则防止条件数据互不重复，但生成 RGB 又坍缩成历史水体骨架。生成前条件审计和生成后 RGB 审计必须使用相同的尺度、归一化、变换和阈值合同。

## 2. 正式阈值合同

- 候选条件只与历史 RGB 做审核比较，历史 RGB 不得成为生成参考。
- 比较覆盖全部历史完整地图，不得只比较同槽位、同景观或活动数据包。
- 水体掩码执行位置与尺度归一化；强形状重复门使用`normalizedWaterShapeIntersection >= 0.45`拒绝（允许值严格小于0.45），值域为`[0,1]`。不同名称的实现指标必须证明同公式、同归一化，不能只改字段别名。
- 生成前条件门禁与生成后 RGB 门禁共用 `0.45`，不得发生阶段间阈值漂移。
- 主河、支流、分汊、汇流、回水汊、岸线、外部水口和道路—水体关系共同构成完整签名，不能只比较主河中心线。
- 道路与水文都从当前测量窗口和当前区域连接实例派生，禁止复用其他样本模板。
- 任一门禁失败时保留图片与证据并进入失败记录；不得无限自动重试、降低阈值或伪造机器通过。

旧两个槽位合同的`strongNormalizedShapeDuplicateMinimumIoU`为0.45，而`duplicateRule`字符串仍含0.55，二者不能任选其一作为当前解释。后继合同必须明确“归一化形状IoU≥0.38且布局IoU≥0.20，或归一化形状IoU≥0.45”的完整拒绝谓词，并将栅格分辨率、变换、适用水域比例、空掩码及证据不足规则一并冻结。0.45不是替代所有其他组合门的唯一阈值；无水样本不得因空掩码互相重合而判为河流模板。

本规则不原地修改旧JSON，不改变当前V2训练Loss或已绑定机器审核文件，也不能替现有代码出具通过证明。数值冲突、旧两槽位作用域和通用程序接入未解决前，相应通用门禁保持未认证；验收至少覆盖阈值下方、恰等阈值、上方、镜像命中、无水及历史比较不完整反例。

## 3. 阈值变更治理

阈值变更属于审核合同变更，必须：

1. 说明变更原因、影响范围和预期风险；
2. 建立独立能力版本，不得在当前失败运行内修改；
3. 对历史通过、历史失败和已知跨模态坍缩样本执行回归；
4. 生成新合同版本，不覆盖旧合同；
5. 保存代码、配置、阈值和回归证据哈希。
