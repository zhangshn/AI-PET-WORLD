## 1. 规格范围

本文定义 AI Painter 的机器审核、自主能力版本发布、失败学习、内部任务票据、训练记录、Token 账本、物理存储、SQLite 索引和只读状态投影。本文不保存某次训练、某张图、某个 Run、某个 Checkpoint 或临时阻断的结果。

Owner职责只引用`DOCUMENT_AUTHORITY_INDEX.md`中的`GOV-OWNER-001`；本规格不定义第二套Owner审批、等待或签名状态。

正式系统记录由本地程序写入 `data/`、`.runtime/`和 SQLite。聊天、页面 GET、Codex 记忆和 Markdown 都不能成为运行状态、授权、审核决定或训练证据。

## 2. 审核链

```text
来源与权属审核
-> VJ-0 身份和绑定审核
-> VJ-1 技术质量审核
-> VJ-2 世界事实与结构审核
-> Professional Aesthetic 审核
-> 全历史构图和语义拓扑审核
-> 能力版本与Runtime发布门
-> 资格登记
```

任一机器硬门禁失败时，图片直接进入失败记录，不得伪造人工或能力发布否决。机器通过只取得当前能力版本声明的后续资格，不能自动成为训练样本；只有已发布能力版本且Runtime发布门通过的候选才能进入正式RuntimeFrame。

审核链及第3节全历史构图／语义拓扑唯一性的适用范围，统一采用[训练数据与来源规则第9.1节](TRAINING_DATA_AND_SOURCE_POLICY.md#91-单世界先行mvp的阶段隔离)。仅在该节规定的新单世界先行MVP作用域身份及程序适用性验证成立时，创作唯一性标记为`deferred_out_of_current_mvp_scope`，不能记为通过，也不能删除历史记录。当前64份内部去重、用途与来源隔离、许可、历史暴露及WorldFacts／条件／RGB一致性仍执行原硬门禁；混合发现分别裁决。超出该作用域时恢复完整唯一性审核。此引用不直接授予旧候选、训练或发布资格。

能力生命周期只使用总体架构第0.4节定义的正式状态：

```text
change_candidate
-> isolated_implementation
-> cpu_contract_verified
-> readonly_gpu_qualified（需要GPU时）
-> controlled_smoke_completed
-> formal_stage_validation_completed
-> independent_regression_completed
-> machine_release_adjudicated
-> released / rejected / rolled_back
```

第一版与重大能力版本使用同一机器发布门。机器发布拒绝阻止该版本发布，但不能删除或改写机器审核；不存在人工首发特例。新图片不继承旧图片结论，同一图片复审必须生成新的不可变审核记录并保留原记录。

## 3. 完整地图机器硬门禁

机器审核至少覆盖：

- 来源、许可、尺寸、哈希、任务和条件绑定；
- 完整矩形世界、无外部背景、无透明空洞、无悬浮切片；
- 原生高分辨率像素风、世界尺度、对象比例和游戏可读性；
- 道路与指定边界真实接触、可走和碰撞关系；
- 水体存在性、入口/出口、流向、岸线和道路避水；
- 当前季节、生态、对象和 23 通道响应；
- 无预设家园中心、建设空地和规则中央留白；
- 连接实例、主题架构、实例细节、条件几何和 RGB 构图的全历史唯一性；
- 未来动态身份与 WorldFacts 可追溯性。

风格一致和构图多样必须分别记录。不能用风格一致掩盖骨架重复，也不能用构图不同放行风格漂移。

生成前审核失败不得调用图像算力，并保存无图阻断记录；生成后审核失败必须保存真实失败图、失败码、位置、指标、时间和证据路径。

每个能力版本必须绑定唯一`reviewThresholdContract`，且审核器在运行前重新计算该文件及实现程序的SHA-256。合同至少完整列出：

```text
reviewContractIdentity / schemaVersion
contractPath / contractSha256
reviewerProgramPath / reviewerProgramSha256
thresholds[] {
  metricId, value, unit, comparator, applicability,
  samplingWindow, aggregation, failureCode
}
referenceSourceIdentities[]
conditionAndMaskContractIdentities[]
nonDegradationPolicy
```

报告中出现阈值名称、“使用冻结阈值”或一个格式正确的SHA字符串不能代替完整合同和重算验证。任一数值、单位、比较符、适用对象或程序血缘未绑定时，不得开始训练或正式审核。

当前Stage4 V2审核阈值的唯一机器合同是`data/ai-painter/system-governance/ai-painter-stage4-v2-machine-review-threshold-contract-v1.json`。候选中立审核边界必须读取该真实文件并重算SHA-256，同时读取当前执行登记与同一执行包记录，逐项交叉验证`registryRevision`、`packageId`、数据发布身份、候选RGB、条件包、参考RGB、四类对象掩码及阈值合同绑定。调用方自报的布尔状态、格式正确的SHA、空登记文件、`latest`指针、历史运行目录或跨执行包证据均不构成可信血缘。正式审核运行器只有在未来Smoke或训练执行包物化时才能登记为当前入口；历史审核运行器只可用于绑定证据复核，不是当前调度权威。

## 4. 道路、水体与岸线审核

道路颜色信号必须按季节与地表状态选择，并通过条件支持的连通分量、覆盖、交集、质心、空间网格、边界接触和完整跨度审核。暖色裸土、旱季草层和岩石高光不能直接计为道路。

水体审核由正式 `terrain_water` 条件决定有水或无水分支：

- 有水：验证淡水信号、覆盖、空间位置、连通和岸线；只有正式阈值合同的`applicability`与条件包声明同时命中时，才额外验证其声明的边界侧、入口/出口和流向。north/south或特定port不是所有有水样本的通用要求；
- 无水：只识别强蓝主导且局部连续的意外水面，不能把阴影或蓝绿色树冠误判为水。

道路、水文和岸线必须分别执行语义拓扑去重。换槽位、换坐标、换宽度、镜像、旋转、轻微形变或修改局部装饰不能绕过同一模板判定。

审核算法修复必须：

1. 保留原审核和原失败学习；
2. 不修改 RGB、WorldFacts、23 通道或阈值；
3. 保存修复前后指标与算法版本；
4. 对历史通过、历史拒绝、有水、无水和不同季节执行回归；
5. 以新审核记录表达同图复审结果。

## 6. 失败学习

失败记录必须结构化为：

```text
failureFamily
issueCodes
affectedRegions
negativeSampleLabels
judgeGapRecord
dictionaryFixTarget
datasetTarget
modelCapabilityTarget
repairConstraints
```

拒绝图不得进入正样本。机器漏判建立 `judge-gap`，规则缺失建立字典或审核器目标，模型失败建立能力目标。失败学习器必须读取完整历史，不得因为记录数量上限、最新指针或新批次覆盖而丢失旧失败。

有界修复必须保持任务范围、WorldFacts、条件、图片和阈值等不变量；不得用降低门槛、删除证据或无上限重试制造通过。

## 7. 政策边界报告与能力版本变更

证据不能唯一裁决时，本地系统失败关闭当前路线并保存不可变裁决报告；触及长期业务目标、使用许可不明确或未登记付费外部资源、或者不可恢复操作时，必须禁止越界动作并生成不可变`policy-boundary-report`，至少包含：

1. 任务和资产身份；
2. 已知业务结论；
3. 机器发现和阻断码；
4. 不能继续的原因；
5. 合同内安全替代路线或停止结论；
6. 必须保持不变的内容；
7. 禁止副作用；
8. 证据路径；
9. Owner未来主动改变业务目标时需要建立的新版本边界。

报告只供观察，不是审批单、Owner动作请求或程序的常规运行入口；当前执行不得等待报告响应。模型、Loss、数据、审核实现、训练计划或正式能力版本变更必须绑定不可变版本、范围、程序和回归证据，并由本地能力生命周期自主推进。训练、生成、固定验证、机器审核、失败关闭、RuntimeFrame发布或回退及终态记录均不得在内部步骤之间请求人工操作。

能力版本变更和内部任务票据都必须具备幂等身份。重复、范围不符、动作不符、哈希不符或已消费票据必须在写入前失败，并保存拒绝证据。

## 8. 自动闭环边界

本地程序在正式能力版本和任务包范围内自主执行：

```text
读取证据
-> 预检
-> 执行合同动作
-> 自动保存
-> 机器审核
-> 失败分类或资格登记
-> 形成新的状态投影
```

程序必须停止的条件包括：

- 证据不唯一且当前合同没有唯一替代路线；
- 需要改变长期业务目标、来源许可、安全上限或使用付费/不可恢复外部动作；
- 数据不足、来源不明、身份冲突或资源门禁失败；
- 连续失败达到停止条件；
- 能力版本或任务票据缺失、无效或已消费；
- 同一条件已有待审、通过或合同不允许重试的失败记录。

完成一个动作只能进入状态机声明的下一状态。执行包只在记录的能力版本、范围、次数、重试和停止条件内有效。

### 8.1 包内自主判断与内部任务票据

内部任务票据是能力版本内的幂等、防重、状态转换、资源配额和证据记录，不是从Owner派生的权限。本地程序为合法的下一状态生成一次性任务票据；票据记录执行包、能力版本、输入证据、程序血缘、动作、状态转换、输出命名空间和消费身份，不能用聊天内容或`latest.json`替代。

机器审核完成后，程序必须用冻结规则自动进入唯一后续状态：通过则进入资格、发布或Finalization；真实视觉失败时，来源训练/审核执行保持`failed_closed`不可变终态，本地能力生命周期编排器必须随后建立独立`failure_boundary_adjudication`后继任务；基础设施失败只有在能力版本明确允许且恢复次数未耗尽时才能恢复；需要修改模型、数据、Loss、审核实现、程序或训练路线时，裁决任务只能关闭旧候选并建立新的`change_candidate`能力版本。审核程序和确定性裁决程序负责正式结论，Codex只可提供技术建议。

后继裁决任务必须使用新`taskId`和`registryRevision`，其稳定初始映射为：

```text
taskKind = failure_boundary_adjudication
lifecycleStage = 来源能力最后有成功证据的正式资格节点
executionState = package_materialized
sourceTerminal = { path, sha256, status: failed_closed }
latestTrainingTerminal = 原训练终态
nextMachineAction = 已注册的CPU只读裁决入口
activeExecution = null（直到裁决任务实际启动）
```

裁决任务实际启动后，仅`executionState`按`adjudicating -> finalizing -> completed / failed_closed`推进；`lifecycleStage`沿用最后成功资格，另存`failedActionId`与`failedTrainingStage`。Full-data screen失败、执行自然结束或某一阶段尝试完毕都不等于`formal_stage_validation_completed`；只有正式阶段全部通过才可使用该节点。无法核实成功资格则返回`unknown_or_stale`，不能猜测。只有裁决确认需要能力变更时才另建`lifecycleStage=change_candidate`的新能力身份。建立或运行裁决任务不得改写来源失败终态、启动GPU、加载失败Checkpoint或自动重训。裁决只能产生唯一有证据结论、新的隔离`change_candidate`或证据不足失败关闭，不得生成Owner等待状态。

所有内部票据、决策报告、拒绝理由和状态转换保存到不可变运行目录并索引到SQLite。票据重放、跨包证据、状态跳跃、未登记的程序血缘变化、超出尝试上限或自由动作注入必须在写入前失败关闭。

## 9. 训练与验证记录

训练程序必须自动保存：

- Run 身份、任务、配置和代码版本；
- 数据包、最终 Dataset 选择和四类 split；
- 模型、Stage、父 Checkpoint 路径与哈希；
- 每个 Epoch 的训练、验证、Checkpoint 选择和最坏轨迹指标；
- Token、CPU、内存、GPU、显存、磁盘、网络、耗时和退出状态；
- 条件证据、算法证据、环境与依赖快照；
- Checkpoint、manifest、progress、日志和 SQLite 索引；
- 成功、阻断、失败、取消和恢复事件。

冒烟只证明程序与最小数据路径可运行；Stage 完成只证明该阶段训练完成；Checkpoint 保存只证明资产存在。它们都不能自动证明视觉能力、训练后验证、正式推理或 Runtime 资格。

challenge 和 regression 的内容及指标不得在训练或 Checkpoint 选择期间读取。阶段执行包已经声明的固定训练后validation、预览复现和机器审核由同包自动完成，并在同一包内使用隔离的子证据命名空间；challenge、regression、额外复审或新证据任务使用独立任务票据和独立证据目录。

## 10. Token 账本

图像扩散训练的本地潜空间 Token 定义为“一个去噪样本前向处理的一个潜空间位置”。它不是 NLP Token，也不是 API 计费 Token。

训练程序必须把 `trainingTokenAccounting` 写入 Epoch、Checkpoint 和 Manifest。账本至少包含：

```text
latentSpatialTokens
latentChannelValues
conditionScalars
rgbPredictionPixels
samplePresentations
optimizerSteps
modelForwardPasses
validationTrajectories
calculationVersion
```

旧运行不得改写原 Manifest；需要补充账本时，使用与原 Run 绑定的不可变旁路账本，并保存来源文件哈希和计算版本。

外部服务 Token 和费用只有在服务方返回权威 usage 时才能登记，禁止按字符、时间、图片数或 GPU 用量估算。

## 11. 当前执行登记、实时状态与投影

当前执行登记是本地系统的机器状态，控制台只读投影。任务是否当前、是否活动以及应继续哪个动作，均不得由GET接口、页面组件或目录扫描结果决定。

### 11.1 四类状态身份

| 字段 | 来源 | 定义 | 空值条件 |
|---|---|---|---|
| `currentProjectTask` | 当前执行登记 | 本地系统当前应推进的唯一项目任务，包括实现、训练、验证、审核、裁决或候选规划 | 未建立任务或登记不可验证 |
| `activeExecution` | 任务锁、进程身份、心跳和执行事件联合验证 | 当前真实运行的执行实例 | 不存在合法锁、进程已退出、心跳过期或身份不一致 |
| `latestTrainingTerminal` | 当前执行登记的训练终态子登记 | 最近一次完成或失败关闭的训练Run | 尚无合法训练终态 |
| `selectedHistoricalRun` | 用户查询参数或页面本地选择 | 当前查看的历史Run | 用户未选择历史记录 |

上述四类身份必须在API Schema中分开返回。一次训练失败后，其机器裁决或下一候选规划可以成为新的`currentProjectTask`；原训练仍是`latestTrainingTerminal`。用户选中某个历史Smoke或Stage时，只能改变`selectedHistoricalRun`。

### 11.2 当前执行登记Schema

逻辑路径固定为：

```text
.runtime/ai-painter/current-execution-registry/
├─ current.json
├─ events.jsonl
└─ transactions/<transactionId>.json
```

`current.json`是指向不可变证据的查询记录，至少包含：

```text
schemaVersion
registryIdentity
registryRevision
eventSequence
capabilityVersion
packageId
packageSha256
taskId
taskKind
runId
lifecycleStage
executionState
activity
nextMachineAction {
  actionId, entrypointId, capabilityVersion,
  sourceEvidence { path, sha256 }, programLineage,
  prerequisites, forbiddenSideEffects
} | null
taskCapsule { path, sha256 }
terminalEvidence { path, sha256, status }
sourceTerminal { path, sha256, status } | null
latestTrainingTerminal { runId, path, sha256, status } | null
supersedes { registryRevision, taskId, runId } | null
recordedAtUtc
recordedAtAsiaShanghai
writerIdentity
transactionId
```

`data/ai-painter/system-governance/ai-painter-current-entrypoint-registry-v1.json`只登记允许调用的程序入口及其代码血缘，不保存项目当前任务，也不得作为本节当前执行登记的替代。前者回答“哪些入口合法”，后者回答“项目现在推进什么、是否有真实活动执行、最近训练终态是什么”。

`recordedAtUtc`用于审计和显示；合法先后关系只由`registryRevision`和`eventSequence`决定。文件系统修改时间、目录名、Run ID字典序、来源类型和页面轮询时间均不得参与当前身份选择。

`nextMachineAction`是已登记程序入口的机器动作合同，不是界面文案或建议。它必须与当前`taskId`和能力版本同修订提交；不存在合法后续动作时可以为空，但不得因程序忘记登记而默认为空。控制台只投影已验证的`nextMachineAction`中的显示字段，不执行它，不根据失败码反向生成它。

### 11.3 唯一写入者与原子事务

当前执行登记的唯一写入者为本地能力生命周期编排器。其他组件只能提交已完成的不可变证据，不得直接写`current.json`。每次更新顺序固定为：

```text
验证前一registryRevision和当前任务身份
-> 重新计算任务胶囊、终态和执行包SHA-256
-> 在SQLite事务内预留新registryRevision与eventSequence
-> 写入同目录临时文件，flush并fsync
-> 以同卷原子替换更新current.json
-> 追加events.jsonl并登记SQLite事件
-> 提交事务并保存transactionId
```

`registryRevision`比较失败、事件序号重复、证据SHA不符或SQLite唯一约束冲突时，必须失败关闭。不得覆盖并发写入，不得为显示正常而只修改指针文件。

### 11.4 合法转换与历史隔离

Smoke、Stage 0/1/2、训练后验证、机器审核、失败裁决和候选规划属于同一能力生命周期中的不同任务类型，不存在全局固定来源优先级。后续任务只能通过合法状态转换和更高的`registryRevision`替代前任。

禁止以下选择行为：

- 某个Smoke目录存在时始终优先返回Smoke；
- 按代码中读取函数的顺序选择第一个非空记录；
- 在不同命名空间内各自选择最新后，不进行全局身份验证就将多个结果组合为一份快照；
- 当当前指针无效时，扫描历史目录并选取一个可解析记录作为降级结果；
- 因用户选中历史Run而改变项目当前任务或下一动作。

历史证据必须保留不可变原始字节。历史Run如需重新执行，必须建立新任务、新Run和新登记修订；不得将原历史Run本身重新标记为活动。

### 11.5 活动执行判定

实时执行状态来自训练控制器、任务锁、真实进程、心跳和不可变事件，不得根据GPU占用推测，也不得把旧`running`文件当成活动任务。`activeExecution`必须同时通过：

1. 任务锁中的`runId`、`packageId`和`capabilityVersion`与当前登记一致；
2. PID存在且进程命令身份符合登记的程序血缘；
3. 心跳未超过能力版本声明的过期时间；
4. 执行状态为`preflight`、`executing`、`validating`、`reviewing`、`adjudicating`或`finalizing`。

任一条件不满足时，不得显示“正在运行”。如果当前登记声明为活动但进程或心跳无效，投影必须标记`unknown_or_stale`并产生只读冲突报告，不得自动补写成功或失败终态。

### 11.6 正式状态与页面活动标签

正式状态不得由控制台另行命名。单次执行只使用总体架构第0.4节定义的执行生命周期：

```text
package_materialized
-> preflight
-> executing
-> validating
-> reviewing
-> adjudicating
-> finalizing
-> completed

任一状态 -> failed_closed
触及冻结政策边界 -> blocked_policy_boundary
```

审核只使用`review_pending -> review_running -> review_passed / review_failed / review_evidence_conflict`。能力变化不作为执行状态保存，而是关闭当前执行并建立`change_candidate`能力版本；政策越界统一为`blocked_policy_boundary`。以上状态均不是等待Owner批准。

页面可以显示“数据准备”“训练”“验证”“审核”“裁决”“归档”等活动标签，但活动标签只是正式状态的`activity`展示。页面显示“空闲”时表示没有活动执行包，不得将“空闲”写为运行终态。

三层状态与控制台投影的固定关系为：

| 机器字段 | 回答的问题 | 控制台允许的使用 | 禁止映射 |
|---|---|---|---|
| `currentProjectTask.lifecycleStage` | 项目当前在能力链上要推进什么 | 顶部当前任务和下一机器动作 | 不得用最近训练终态覆盖 |
| `activeExecution.executionState` | 当前执行包正在进行哪个正式步骤 | 运行/验证/审核/裁决/收口动态状态 | 无进程时不得显示运行中 |
| `machineReview.status` | 当前候选的机器审核证据处于哪一步 | 审核详情、指标和失败码 | 不得把`review_failed`显示成“等待验证” |
| `latestTrainingTerminal` | 最近一次训练已经如何结束 | 历史终态及证据入口 | 不得代替当前裁决任务 |
| `nextMachineAction` | 本地编排器已注册的唯一后续动作 | 只读展示动作、前置和禁止副作用 | 页面不得生成、改写或执行 |

“训练完成，等待验证”只能在同一执行包已合法进入`validating`且存在有效活动执行时显示。训练终态已经失败关闭、审核已结束或当前任务已是`adjudicating`时，该文案属于错误投影。

### 11.7 读取失败与中断恢复

控制台读取当前登记时必须验证Schema、修订、写入者、事务、路径边界和SHA-256。任一验证失败时：

```text
currentProjectTask.status = unknown_or_stale
activeExecution = null
stateProjectionIntegrity = evidence_conflict
```

控制台保持GET只读，不得修复指针、补写事件或更改SQLite。本地编排器可依据`transactions/`与SQLite事务日志幂等恢复未完成提交；恢复后必须重新生成完整快照，不得重用损坏指针或历史Run充当恢复结果。

### 11.8 必须通过的状态投影回归

状态投影实现至少必须通过：

1. 旧Smoke、更新Stage 0失败终态和最新候选规划同时存在时，`currentProjectTask`指向规划，`latestTrainingTerminal`指向Stage 0，Smoke仅作历史记录；
2. 选中历史Smoke后，全局当前任务、最近训练终态和下一动作不变；
3. 当前登记SHA不符、证据路径不存在或事务不完整时，返回`unknown_or_stale`，不回退旧Smoke；
4. 两个写入者竞争同一修订时，只有一个事务可提交；
5. 文件更新成功但SQLite事务中断时，恢复程序只能完成原修订或恢复上一完整修订；
6. 旧`running`文件存在但PID或心跳无效时，`activeExecution`为空并显示证据冲突；
7. 任意新增命名空间未经当前登记写入时，不得影响控制台的当前身份。
8. Full-data screen机器审核失败时，来源执行终态字节不变，新修订建立`failure_boundary_adjudication`当前任务并保留原`latestTrainingTerminal`。
9. `nextMachineAction`缺少入口登记、程序血缘、来源证据或前置条件时返回证据冲突，不得显示或执行部分动作。
10. 控制台查看历史失败Run时，当前裁决状态、`nextMachineAction`和最近训练终态不变。

### 11.9 原生执行器启动前失败与遗留占用审计

本节仅定义训练执行基础设施的占用与失败恢复，不改变模型、来源、划分、数值容差、视觉审核、资源上限或能力发布资格。旧规格原始字节须保留供历史复核；当前程序采用与历史执行符合状态分别记录。

原生执行器编译在私有UUID证据目录内先行完成，所有构建字节与失败证据纳入原任务预算；编译成功后才以独占创建方式取得全局执行guard，且必须在任何原生owner或训练worker启动前取得guard。入口仍拒绝已有未知guard；编译期间出现并发guard时，后续独占创建必须拒绝，不能覆盖或抢占。编译失败不得自行重试、消费额外训练次数或创建训练guard。

启动前失败只有在同一个仍存活的调用内证明编译已经正常返回或以明确非零状态结束、自己未取得guard且尚未尝试spawn时，才可记录`same_live_call_no_guard_or_native_owner_created`。原始错误与`cleanupConfirmed=false`的原始回执先不可变保存，再写明上述依据的最终回执；这表示没有创建受管Job，不得伪造`activeProcessesAfterCleanup=0`或活跃Job清理证明。超时、退出不明、源码变化、失败证据写入失败或仅有从磁盘解析的回执都不能签发该依据。取得guard或尝试spawn后，仍须满足原活跃owner句柄、身份绑定、先入Job后恢复、kill-on-close、空Job及可靠流回执要求；不得借用前一调用清理结论。

遗留guard不能追溯性获得新的启动前回执。仅对显式绑定的一次历史编译失败，可由本地程序独立进行`historical_pre_spawn_guard_adjudication`：逐字节重算guard、原执行包／源码闭包、原编译输入快照、编译失败、原异常回执、消费／终态／登记及进程创建身份；确认原正常非零编译异常与原调用控制流严格对应，且该调用未到达owner spawn；核验当前登记没有活动执行及相关执行进程不在运行。不存在的二进制、过期心跳、PID不存在、合法SHA格式、旧磁盘空Job或调用方布尔值单独都不构成判据。任何身份冲突、证据缺失、无法排除已spawn或进程查询不完整均拒绝处置并保留guard。

满足全部条件的历史占用只允许同卷、原字节保留的审计隔离，不允许补造活跃清理、覆盖原失败、修改已消费执行或重放旧包。处置前写入完整不可变审计与目标SHA，处置时再次核验原guard及登记；目标不符或归档路径越界／冲突则停止。隔离结果必须明确`historicalCleanupCertified=false`及原执行仍为失败；中断后只能核对同一事务及原／隔离位置，不得删除未知文件、改变目标或自动另做一次。已有started证据或不能满足本节的未知guard不适用此例外。

新的合法执行仍需独立身份、当前程序CPU证据及自身GPU准入；审计隔离不授予训练、Stage4、模型、Runtime或能力发布资格。不建立Owner日常审批状态，也不把可选诊断迁移作为正常训练额外前置。对应回归至少覆盖：编译先行、编译失败不占锁、失败记录IO拒绝、同调用证明不可重放、并发／未知guard拒绝、spawn后保持原清理门，以及历史审计错SHA／错身份／缺证据／已started／事务中断拒绝。

### 11.10 执行输出与终态回执的预算分区

原生owner启动前必须在原任务硬总额内预留可容纳原始活跃回执、最终回执、原生观察及有界外层成功／失败终态的容量；预留只能减少工作输出额度，不能增加原CPU／GPU机会、墙钟、流上限或输出总额。回执最大封套须计入原生proof、身份与构建元数据、JSON转义、保留的stderr及协议错误；原始／最终回执不能在保存后仍要求重复保留同一未使用空间。预留或输入／构建预测不足时必须在取得guard前拒绝，不依赖定时轮询补救已知不足。

普通工作进程只获得扣除原生终态预留后的输出上限，仍须为自己的失败终态保留空间。审核投影PNG和详细审核报告属于普通产物，不得放入小容量终态作用域；有界最终记录才使用外层终态额度。父进程只能在当前受管调用中以专用写入作用域使用原生回执预留；该作用域不通过可重放的JSON或环境布尔字段授予清理权。清理确认仍采用第11.9节的活跃owner／身份／可靠流要求，超限、IO失败或清理不明保持失败与guard，不以预算规则隔离已启动的遗留guard。流字节必须从实际累计总额扣除；工作输出、构建、原始／最终回执及外层终态总和不得超过原硬上限。后续阶段可以从精确绑定的不可变回执读取资源账本，但该回读只用于预算，不授予历史Job清理、重放或释放guard的权限。

审核终态若保存于审核目录之外，必须在写入前显式纳入对应finalization与capsule文件的累计计量；不可逐文件重新获得一份终态额度，也不把整个训练Run转移进审核额度。作用域拒绝未登记的目录外写入，已写入的明确终态文件同时计入后续写入与原硬总额。

CPU任务的累计账本须包含该任务根和所有明确绑定的前批／当前原生构建命名空间；同一命名空间只计一次。逐一核验Run派生身份、指针与绑定原始字节，缺失指针、错误绑定、跨Run改写、内部链接或超出命名空间数量上限时拒绝，不能静默漏计。只检查已绑定任务根，不从其他历史目录选择执行。输入复制预测须至少覆盖实际源码／元数据复制，旧失败字节继续计入原任务；耗尽的任务不得通过移走证据或新名称静默重置额度。

对应验收须覆盖：前批外置构建累计计量、普通输出预算拒绝后仍可持久化原始／最终回执且保持失败状态、开锁前容量拒绝、错绑／丢失指针拒绝、实际流计量、外层终态限额与原硬总额。隔离回归通过不等于当前源码完整生命周期CPU、GPU或训练资格。

### 11.11 已启动执行的跨内核重启占用恢复

本节适用于原生owner已启动、可靠活跃清理回执未持久化且全局guard遗留的单次执行。恢复对象是执行占用，不是训练状态或模型资格；第11.9节的启动前例外不适用。

#### 11.11.1 责任与输入

恢复程序独立读取并核验：明确目标guard及SHA-256、原started记录、原构建输入与二进制、原观察、已保存的原失败证据、当前登记及重启前主机观察。当前主机证据由本次程序直接查询Windows原生接口，不接受调用方或历史JSON替代。

原观察存在时继续使用V1完整证据分支，不得通过缺失声明跳过已有文件、摘要冲突、权限错误或链接。CPU原观察缺失例外使用`ai-painter-owned-worker-reboot-recovery-profile-v2`及`cpu_timeout_missing_native_observation_v1`，仅适用于CPU准备已启动、原回执记录`wall_timeout`、没有实时R／完整清理证明且guard保留的失败；不适用于GPU、训练或其他未知故障。训练因完整内核重启而没有持久化原终态的情况，只适用第11.11.5节的独立V3分支，不继承V2例外。

V2恢复器须重新计算原guard快照、started中的owner身份及命令绑定、构建源码快照与二进制、原helper快照、CPU request及已消费记录、原失败记录和最终原生回执。各记录须绑定同一guard、Run、包与CPU准备；原失败不得声称清理、普通写入或guard释放资格。旧源码按原构建及helper不可变快照核验，不要求当前修复源码等于旧版本。预期缺失路径只能是原构建二进制同目录的`cleanup-observation.json`，恢复器在每次审计中直接确认不存在；存在的文件、悬空链接、访问失败及其他IO错误均阻断，不能伪造空观察或未知root PID。

缺失分支仍须满足REC-BOOT-001至006；新的完整内核开机周期必须晚于原执行、原失败和精确绑定的重启前原生查询。保留当前登记完整性、完整进程查询、独占租约、同卷事务与原字节隔离要求。原观察缺失不证明历史清理，不授予CPU、GPU或训练资格；输出明确`nativeObservationMissing=true`及原失败／回执绑定。程序不发起重启，也不得在同一内核周期根据PID消失解除占用。

恢复程序不发起重启。机器发生完整内核重启后，才可核验该分支；注销、睡眠、休眠、应用重启或快速启动不自动满足条件。Windows日志与CIM读取失败、内容冲突或无法证明新内核开机周期时，保留占用并返回阻断。

#### 11.11.2 恢复要求

| 条款 | 责任组件与条件 | 结果及验收 |
|---|---|---|
| REC-BOOT-001 | 主机查询器取得同一主机的MachineGuid摘要、Kernel-General事件12及CIM LastBootUpTime；两种开机时间一致，当前开机时间晚于原执行及重启前观察，事件序号严格增加 | 同一内核周期、异机、事件缺失、时间或序号冲突均拒绝；原PID消失或磁盘空Job记录不能单独通过 |
| REC-BOOT-002 | 证据验证器重算目标guard、started、构建快照与产物、helper快照、原观察及失败证据；仅第11.11.1节明确的V2缺失分支可替代原观察输入，其余身份链完整 | 错SHA、错身份、未定义的缺证据、目标改写拒绝；不补造原始活跃清理回执 |
| REC-BOOT-003 | 当前登记读取器验证正式登记完整性且无活动执行；本次完整进程查询排除目标执行、原生owner及冲突的本地模型worker | 查询失败、候选进程身份不完整、活动登记或冲突进程存在时拒绝；PID复用按创建身份判断 |
| REC-BOOT-004 | 处置器取得独占恢复租约，保存不可变审计与事务意图，再核验源guard及当前登记；归档目标为同卷私有事务目录 | 原guard逐字节隔离，归档冲突及并发处置拒绝；不覆盖其他guard、归档或失败证据 |
| REC-BOOT-005 | 同一事务中断后，恢复器核对原位置、隔离位置、意图与审计SHA | 仅补齐原事务；新guard、两处冲突、目标变化或事务不符拒绝；不重复隔离或消费旧任务 |
| REC-BOOT-006 | 结果记录器写入隔离依据及原始证据引用 | `historicalCleanupCertified=false`、`oldExecutionMayReplay=false`、`trainingQualificationGranted=false`；新训练仍需新CPU、执行包及自身GPU证据 |

#### 11.11.3 输出与失败

恢复输出包含`caseId`、输入绑定、原guard身份、重启前后主机证据、当前登记绑定、命中或拒绝条款、事务身份、原字节隔离绑定及唯一处置状态。合法状态为`eligible_for_quarantine`、`blocked`、`quarantined_not_cleanup_certified`；`eligible_for_quarantine`是预检结果，不表示已处置。中断恢复另记录`recoveredSameTransaction`，保留首次意图与审计。

本地实现限时查询、限制证据及输出总字节，超时、IO或证据错误保持失败关闭。处置期间同时占用正式登记的写者租约；原guard在原子隔离前阻止普通worker进入，隔离后出现新guard不得被清理或覆盖。程序读回已完成事务只核验并返回原结果，不重复执行或追加训练；当前入口采用状态由机器证据记录，不从本节自动获得训练资格。

进程硬中断可能遗留恢复租约和登记写者租约。同一内核周期内保持阻断；只有再次证明新内核开机时间晚于该租约创建时间，且租约明确绑定同一恢复事务、原guard及程序摘要时，才允许保存租约原字节和本次原生证据，使用Windows独占文件访问完成摘要比较与同事务换主。未知租约、原周期、错身份或并发摘要变化均拒绝。此分支不依据PID消失抢占，不接管其他登记写者，不执行自动重启。

#### 11.11.4 必须验证的场景

验收至少包含：同主机新内核周期正例；同周期、休眠／快速启动未形成新内核证据、异机、错SHA、缺失记录、活动执行、进程冲突、PID复用、查询失败、归档冲突、独占租约冲突，以及意图后／隔离后／结果写入前中断。隔离测试使用合成主机和私有guard目录，不能宣称真实主机重启验收已完成。

V2另须覆盖真实文件读取及摘要重算的完整缺失正例，已有观察／悬空链接／权限错误、错回执／owner／guard／Run／包、GPU或训练失败、已有清理资格、消费重放、源码快照变化、错误缺失路径、旧开机周期及缺失其他原证据反例；保留V1及同事务中断恢复回归，不以夹具通过签发真实隔离资格。

#### 11.11.5 训练系统中断的登记与占用收尾

`ai-painter-owned-worker-reboot-recovery-profile-v3`的`training_kernel_interruption_v1`仅收尾已启动训练因完整内核重启遗留的登记和占用；不恢复权重、不重放原包、不自动重训、不调查或改变操作系统。程序复用本节原生主机查询、正式登记事务、独占租约及同卷隔离，不另建执行后台。

| 要求 | 可验证条件与失败行为 |
|---|---|
| 原执行身份 | 从显式绑定的原登记、原包、冻结计划、execution-lock、started和commandBinding重新计算摘要；Run、包、能力、原runner及owner、guard、原构建与helper逐一一致。原包和计划的全部源码按原文件或摘要相同的不可变原字节账本核验；不能用当前修复源码冒充旧版本。 |
| 中断边界 | 绑定原执行前已保存的同机原生主机观察；其开机周期早于原执行。当前程序直接查询同机Kernel-General事件12、CIM开机时间和完整进程身份，证明新内核周期晚于原执行及最后持久化进度，且不存在相关worker。PID消失、文件日期、调用方布尔值或仅一份当前日志均不够。 |
| 损坏与缺失 | 心跳只能为明确绑定的全零原字节，或身份一致且已过期的合法记录；全零原件必须保存，不改写成有效心跳。原训练worker终态及finalization必须确实不存在；已存在的成功、失败、访问错误或链接不能被忽略。原生观察只允许精确构建目录下的cleanup-observation.json确实缺失，不补造原观察或清理回执。 |
| 终态登记 | 普通登记读取仍拒绝损坏心跳；独立收尾入口在重新核验全部输入及新内核证据后，只能通过既有登记文件、事件和SQLite事务把精确原Run登记为`failed_closed`，原因`training_system_interrupted`。保存最后真实进度，选中Checkpoint为空且不授予模型资格。旧登记原字节、原进度、消费及训练记录均保持。 |
| 占用隔离 | 新终态必须明确引用原登记摘要及本次profile；guard继续阻止新worker，直至正式登记读回一致、独占恢复和登记租约取得并重复核验通过后，同卷原字节隔离。登记后隔离前中断，只接续同一profile；隔离事务中断沿用REC-BOOT-004至005，不改目标、不覆盖新guard。 |
| 输出与边界 | 分别记录登记事务与隔离事务身份；`historicalCleanupCertified=false`、`oldExecutionMayReplay=false`、`trainingQualificationGranted=false`、零自动重试。没有原训练终态时，本次终态表示系统中断，不将其解释为已经证实的训练实现或模型缺陷；训练、画质、离线自主及Stage4资格仍独立验收。 |

回归必须覆盖真实字节与摘要核验、全零心跳和合法过期心跳正例，同周期／异机／活跃worker／错Run或包／源码缺失或错摘要／任意未知心跳／已有终态／权限错误／链接反例，正式登记与SQLite一致性，以及登记后、隔离前后中断的同事务接续。私有夹具不得代替真实项目收尾；真实采用须保留独立核验记录。

### 11.12 训练完成后的只读审核恢复

训练权重与审核执行分别保存终态。训练已正常完成、固定Checkpoint集合及机器选择可复核，而审核因程序或基础设施异常在取得结论前停止时，可建立独立、不可变的只读审核恢复任务。恢复不重放原训练或原审核身份，不覆盖失败、原包、权重、消费标记或产物；视觉审核已作出的拒绝不能用本分支改称程序失败。

| 要求 | 判定与责任 |
|---|---|
| 输入身份 | 绑定原训练包、计划、成功终态、全部Checkpoint、选中权重、原审核失败、配置、数据和程序闭包，重新计算真实SHA；当前登记不得有其他活动执行 |
| 程序修复 | 仅审核传输、目录消费和结果登记实现可变；历史传输代码用原字节快照解释，实际模型、数据读取、Checkpoint解码、数值及审核器必须与原训练身份一致。当前修复代码、测试和CPU验收另行绑定，不将历史源码称为当前执行源码 |
| 执行与预算 | 一次CPU审核恢复、零自动重试、CPU2线程、零GPU／梯度／优化；只对同一8份validation及既定基准各前向一次，最多16次模型前向。原审核及恢复的墙钟累计不超过120秒、输出与流累计不超过16MiB；原构建、回执、失败及新产物一并计量，不以新目录重置额度 |
| 输出消费 | 预建空计量目录不是已消费。使用独占创建的一次性标记；有标记、部分产物、内部链接或非目录均拒绝重放，失败保留标记及原始错误 |
| 结果登记 | 当前任务的终态显式绑定原训练终态、审核报告、候选／原图、机器审核或程序失败；通过唯一登记写入器原子提交文件、事件和SQLite，保留原`latestTrainingTerminal`。控制台沿同一绑定链只读展示，不扫描目录或把候选可见等同于合格 |

回读旧原生回执只能用于原身份及累计预算核验，不能签发历史活跃清理；恢复调用必须取得自己的原生活跃清理证明。恢复前登记原失败，恢复结束登记真实结论；清理未知时保持占用与失败，不伪造无活动执行。新CPU验收须覆盖空目录、重复／并发消费、部分产物、路径越界、源变化、跨Run／包／权重错绑、预算耗尽及成功／程序失败的可观察性。恢复结果不授予正式Stage4、视觉批准、Runtime或能力发布资格。

### 11.13 有界停止流程的源码闭包一致性

停止请求组件与执行登记桥接采用`owned-stop-source-closure-v2`内部实现合同，源码角色数量上限统一为256，与现行生态执行登记合同一致。此变更只解决完整程序血缘的数量兼容，不改变请求Schema、认证、停止权限、资源配额或清理证明。

| 要求 | 实现与验收 |
|---|---|
| 角色数量 | 按完整`programLineage`和`programBindings`逐项核对，必须非空且不超过256；两者角色集合及每项路径、SHA须一致。179项和256项在其余证据合格时可被接受，257项在任何停止消费前拒绝 |
| 字节上限 | 单份源码读取不超过1MiB，全部角色累计不超过16MiB；同路径的多个角色仍分别验证并按原累计语义计量。不截断角色、不遗漏依赖、不通过去重缩减血缘或重置额度 |
| 证据身份 | 从精确绑定的真实执行包读取并重新计算全部源码字节，调用方声明、合法SHA格式和历史通过记录不授予资格；缺失、篡改、重复角色、角色集合不符或超限均拒绝 |
| 目录边界 | 只接受当前存储合同的正式项目运行根映射，固定逻辑根、物理根及映射身份；根替换、配置变化、子目录链接和越界仍拒绝。请求证据账本不继承运行根的重定向例外 |
| 不变边界 | 会话、CSRF、HMAC、目标Run／包／PID创建身份、保留调用、登记修订、新鲜度、刷新截止、未结束读取并发限制、幂等及停止理由UTF-8字节上限保持原合同；不得以提高角色数量扩展上述边界 |
| 采用状态 | 组件测试、实际包兼容、默认正式读取器、真实保留调用及原生停止分别记录。隔离兼容通过不表示已接入生产，不执行真实停止，也不签发清理或训练资格 |

CPU验收须包含179／256项正例，257项、缺失或篡改末项、角色集合错配、单文件及累计字节超限反例，并保留既有认证、映射、快照新鲜度、刷新超时、并发、重复消费和未知清理拒绝测试。测试使用私有目录及合成调用，不更改正式登记、API、原生执行器或正在运行的训练。

### 11.14 CPU负向输入的限定链接与资源计量

本条是第11.10节内部链接默认拒绝规则的一项限定测试输入例外，仅适用于AI Painter主体规格第9.6.39.1节。它不允许生产输出、GPU、训练、数据来源、审核或Runtime目录使用链接；第11.13节停止源码读取也不继承该例外。旧失败执行原样保留，不重放、复用资格或追溯性改写其结果。

负向输入作用域只能由当前CPU原生适配器根据精确已绑定入口、request、Run／包、测试源码及正式物理映射建立；实际计量权限保留在当前调用中，不由可重放JSON或环境开关建立。固定布局最多三个目录链接，链接及其普通目标均在同一个本Run负向输入根内，与其他账本根不重叠。未登记跳转、文件链接、错误目标、根或目标目录替换及嵌套跳转一律拒绝。读取器对这些输入的业务拒绝规则保持不变。

计量逐项核对普通文件实际字节，并核对每个登记链接的位置、类型、目标及当前文件身份；不得跟随链接、访问根外目标或重复遍历同一目标文件。每个登记目录链接始终预扣16KiB，作为Windows重解析数据的保守上界，明确记录为预扣额而非实际测量值；三项累计最多48KiB，输入声明、目标文件、日志和终态另外按实际字节累计。此预扣从原8MiB内部扣除，即使链接尚未建立或已经移除也不返还。无证明支持的链接尺寸不能记零或另领额度。

连续监控只允许精确登记的测试链接经历建立及移除。扫描中遇到该链接已移除时仍保留完整预扣，最终独立核验其不存在；不能把此规则推广到普通文件消失、账本根缺失或其他IO异常。普通输出继续由原严格规则计量。构建、流、原始与最终回执及失败预留依第11.10节合计，本节诊断CPU调用含启动及终态最多240秒、CPU最多2线程、输出8MiB、尝试1／重试0，不另建账本、后台或扩大字节总额。

本节240秒只对应主体规格第9.6.39节完整组件验收与新程序自身受管CPU预检，不延长其他CPU／审核、GPU或训练调用。内外层共享同次截止，子调用不得重新计时；120秒心跳有效期、清理及全部资源计量要求保持。旧120秒调用的实际时间、已消费状态、失败和未完成清理证据原样保留，不追溯性认定通过；后继使用新规范及程序身份。

CPU准入结束前必须从本次实际保留调用验证进程清理，并重新核验全部登记链接已移除、根和目标身份有效、预算未超限。两类清理分别记录。链接仍存在、身份冲突、资源失败或清理不明时保持失败、不进入GPU；不得删除未知链接、覆盖失败文件或将夹具结果伪称训练证据。所有成功、失败和辅助记录保留真实路径、原始时间及摘要；原生错误至少记录被拒绝的逻辑路径，已发生且缺路径的历史错误仍保留unknown。

验收至少覆盖三个真实目录链接被业务Reader拒绝而正常计量、不跟随外部目标、错误或未登记链接与文件链接拒绝、普通输出及非CPU阶段仍拒绝、目标／根替换、已知链接移除与未知文件消失的区别、全目录累计预算及48KiB预扣、清理未完成拒绝、旧调用或marker不能激活作用域；既有CPU原正反测试全部保留。

主体规格第9.6.40节的短程画质验证可复用本节CPU负向输入计量，但必须重新绑定其自身精确CPU入口、程序及测试；240秒／8MiB、三个固定链接及全部实际观察和清理规则保持。该采用不允许CPU旧资格复用，不开放训练、GPU或审核链接，也不修改第9.6.39节诊断执行的历史身份。

| CTRL-LOCAL-005 结果分层 | 请求已接受、已消费、理由已交接、进程停止、原生活跃清理和Checkpoint是否已落盘分别记录。前三项不能推导后三项。真实停止保留原失败／停止终态及已有合法产物，只有本次可靠空Job和流回执可释放自身guard；磁盘回执、调用方布尔值或事后PID消失不授予清理权 |
| CTRL-LOCAL-006 独立验收 | 在无竞争训练时，用同一正式读取器、保留调用及原生Job取得正常、程序失败、操作者停止的真实CPU证据；受管CPU最多2线程、120秒、8MiB，尝试1／自动重试0。合成测试与生产证据分开，真实停止仅针对验收自有任务，不为验收打断活动画质训练。Codex不参与运行衔接的离线验收结果单独记录 |
| CTRL-LOCAL-007 自动运行准备 | 准备并启动模式只选择既有机器注册表明确登记的能力及固定候选配置；本地程序重新核验真实源码、数据、模型、规范和资源身份，建立新Run与包身份、输出命名空间及一次性消费记录，完成本轮受管CPU、精确计划和执行包物化，再交给既有后台生命周期。调用者不编写执行包、不拼接SHA、不声明资格；不得接受任意脚本、路径或覆盖训练参数。CPU及后续GPU仍取得自身证据，不复用旧失败或旧资格；准备失败保留终态并禁止后续GPU。各步骤采用对应冻结合同的原预算，准备流程不增加恢复次数或人工审批门 |
| CTRL-LOCAL-008 启动失败可观测 | 同一既有启动尝试命名空间保存有界标准输出、标准错误和生命周期建立前的失败证据，绑定nonce、运行器及执行包摘要、进程创建身份和实际时间；缺少尚未产生的身份须明确记录，不伪造运行登记。日志纳入原预算、不保存密钥、不新增无限日志或重试。进程创建回执不代表流程完成；进程早退且缺少可信终态时显示失败或证据不足，不能显示已迁移成功 |
| CTRL-LOCAL-009 完整本地发起验收 | 使用固定入口从登记配置开始，由本地程序自动准备并接续到终态；发起端在准备尚未完成时退出，剩余步骤不读取聊天、不调用外部AI、不下载缺失依赖。在本地数据、运行时及必要本地认证已具备的环境验证正常、失败及停止，并以至少两次独立新运行证明下一轮不需要修改源码、重接接口或人工制作包。CPU夹具只证明所验控制链，真实GPU、Checkpoint和审核结果另按训练合同取得；生产认证、实际网络隔离、浏览器查看等未验证项单列，不能由夹具或进程存活推定通过 |

兼容改动必须先完成接口与测试核验，再冻结新程序身份。训练与迁移可以并行建设，但同一源码由单一执行任务修改；GPU、登记写者、全局guard及受管Job不得因多窗口被视为隔离资源。未采用本节的历史程序保持原行为，不能凭新文档给旧执行补造停止或离线能力。生产操作者认证缺失时控制请求明确拒绝，不能生成密钥、伪造会话或静默绕过；该失败不改变本地系统依据生效合同自主运行的主体边界。未知故障仍安全停止，自动准备和连续执行不等于自动诊断、改代码或无限继续研发。

#### 11.15.1 稳定操作者认证的部署与采用

部署配置与运行控制是不同操作。明确限定的本地部署步骤可以初始化缺失的稳定签名配置并使既有服务采用它；start／stop、会话签发及后台准备仍不得自动生成密钥、轮换已有密钥或采用开发进程随机值绕过认证。此区别不引入本地AI日常训练审批。

| 要求 | 部署与验收边界 |
|---|---|
| DEP-AUTH-001 精确配置 | 仅使用项目既有部署配置与`AI_PET_WORLD_OPERATOR_SESSION_SECRET`；配置不存在时使用系统安全随机源形成至少32字节熵的稳定值。已有有效值不轮换，冲突、短值、非法编码、链接、硬链接、大小或身份变化均拒绝。保留其他配置原字节；不得更改User／Machine环境、依赖或训练参数 |
| DEP-AUTH-002 秘密保护 | 配置、暂存和可恢复备份只对实际运行账户与必要系统身份开放；秘密写入前先建立权限。秘密、Cookie、CSRF及其摘要不进入命令行、日志、提示、机器公开报告、Git或训练来源闭包。报告只保存非秘密部署状态、来源类别、权限检查、服务身份与采用结果；既有日志脱敏仍执行 |
| DEP-AUTH-003 一致采用 | 会话签发服务、外部入口与后台通过相同官方配置加载规则取得稳定值。文件写入不证明存活服务已采用；必须验证真实新会话与独立进程的现有HMAC／CSRF校验。验证材料仅保留在内存，不伪造会话或将开发fallback算为生产一致性。旧会话失效与采用失败分别记录 |
| DEP-AUTH-004 服务范围 | 需要重新加载时，先核验项目根、监听端口、精确进程创建身份及父子关系，只重载该项目原服务模式。无活动训练及未知guard时才进行；不终止其他Node进程、不重启Windows／Codex、不构建新后台。后台启动隐藏窗口，记录非秘密新进程身份、可用性及错误；失败保留可恢复配置，不无限重启 |
| DEP-AUTH-005 验收分层 | 先完成不接触真实配置的隔离正反测试，再核验真实部署和独立认证采用。CPU最多2线程、单次测试120秒／8MiB、一次部署／一次服务重载，无自动重试。部署成功不等于CTRL-LOCAL-006／009的真实正常、失败、停止和网络隔离通过，也不提供模型、GPU或训练资格 |

未完成稳定部署或真实采用的入口继续按第11.15节明确拒绝。部署工具不成为start／stop的隐式前置脚本，也不为当前或未来运行生成Owner等待状态；未知故障仍按本地合同失败关闭。

## 12. 物理存储与 SQLite

AI Painter 独立数据根使用：

```text
D:\AI-PET-WORLD-DATA\hot\runtime
D:\AI-PET-WORLD-DATA\cold\runs
D:\AI-PET-WORLD-DATA\catalog
D:\AI-PET-WORLD-DATA\migrations
```

项目内 `.runtime` 是兼容逻辑入口，只能指向一个正式热层，不能产生第二套可写业务身份。

文件是正式证据，SQLite 是目录和查询层。程序写入运行状态、事件、Manifest、图片、Checkpoint、审核或失败后，必须同步或在 Run 结束时事务化登记 URI、字节数、时间、SHA-256、Run ID 和资产类型。

`latest.json` 只作指针；SQLite 也不能替代原始文件。GET 页面不得递归扫描全部运行目录或补写索引。

完成 Run 进入冷层前必须生成不可变归档 Manifest，记录原相对路径、文件数、总字节、逐文件哈希和归档哈希；只有文件校验和 SQLite 事务成功后才能标记 `archived`。迁移与备份删除只能在生效存储与保留策略已明确允许、绝对目标逐项校验、可恢复证据和内部任务票据齐全时执行；未定义或证据不完整时必须禁止，不进入Owner等待状态。

## 14. 控制台边界

训练监控台是只读观察入口，操作台才是受控写操作入口。监控台展示当前任务、Stage、Epoch、参数、数据、Token、硬件、日志、Checkpoint、审核、阻断和能力迁移状态。

历史 Run 按 Run ID 独立查看。没有程序保存的预览、去噪节点或诊断图时，页面必须显示“无证据”，不得伪造图片或把训练原图冒充 Epoch 输出。

GET 页面不得改变台账、更新时间、审核、训练资格或当前指针。控制台按钮只能向本地任务编排器提交任务或项目级决定，页面组件不得直接写业务文件。

## 15. 能力迁移记录

本地自研 AI 能力迁移注册表保存每项能力的当前执行方、目标执行方、成熟度、测试证据、阻断和回退方案。控制台只读展示，不在页面内自动切换执行方。

Codex 可以按项目任务建设代码、编译测试和处理复杂诊断；已达到本地闭环验收的能力由本地系统执行，Codex 降为只读监控与证据核验。迁移不能让 Codex 成为审核、发布或 Runtime 的必要依赖。

### 15.1 生命视觉的审核责任

完整MVP除既有自然地图门外，必须验证主体规格第18节八组场景：人物档案来源与身份、五类现实动物／生境、可见生命状态、时序稳定、行动约束、存档恢复、训练隔离及正式展示。VJ-0检查实体／档案／状态／世界身份与hash，VJ-1检查完整画面质量，VJ-2检查物种、姿态、状态表现、位置、遮挡和碰撞语义；任何层不适用必须有事实与审核合同依据，不能默认通过。

健康状态的真值来自Runtime快照，审核器只判断视觉是否表达了已声明体征；不能凭RGB诊断后反写病情。身份一致性、姿态及症状审核器未建立时应记录缺验证能力并阻断生命版本发布，不能使用颜色或纹理分数冒充语义准确率。

### 15.2 进度、故障与恢复的可观察性

每个任务的资源合同必须绑定心跳周期、陈旧阈值、执行超时、最大恢复次数及恢复前置条件。监控至少返回：查询时间／时区、最后有效心跳、最后业务进展、当前动作、证据路径、阻断码与下一动作。心跳刷新不等于Epoch或业务进展，GPU利用率也不证明任务健康。

“无活动执行”“正在执行但无新业务进展”“状态已陈旧”“已失败关闭”“下一包尚未物化”必须分别表达。未有进度证据不能承诺剩余时间；五阶段计数是里程碑计数而非剩余耗时或完整MVP百分比。聊天的十分钟提醒只是外部观察，不是本地任务心跳，也不能作为Runtime依赖。

CPU资格必须映射正式`cpu_contract_verified`枚举；旧别名只能通过明确迁移规则解释并保留原值与来源。`nextMachineAction`必须按第11.2节提供结构化身份，裸字符串或脚本存在不能证明动作可以被安全消费。

进程／主机中断恢复先核验任务锁、心跳租约、消费记录、事务日志、程序血缘与原始产物，再幂等补齐同一执行的终态或有限恢复；不能仅因PID不存在重训。恢复测试必须覆盖训练后未审核、审核后未登记、文件写入后SQLite未提交、正式帧发布中断四个窗口。

## 16. 验收标准

审核、自动闭环与存储系统合格必须证明：

1. 所有写操作在执行前验证能力版本、任务票据和输出边界，并原子登记。
2. 机器审核、能力版本发布验收、训练资格和 Runtime 资格相互独立。
3. 失败、复审和修复证据不可变且可按身份完整追溯。
4. 训练、验证、Token、硬件、Checkpoint 和算法证据由程序自动保存。
5. 实时状态来自最新合法机器证据，不被旧指针覆盖。
6. 文件、SQLite 和物理存储身份一致，可校验、归档和恢复。
7. 页面 GET 只读，历史 Run 分页且不扫描全盘。
8. 关闭 Codex 或丢失聊天不会破坏正式流程和状态解释。

具体 Run、样本、哈希、指标、资源阻断、内部票据消费和历史授权证据只保存在机器记录中，不写入本规格。
