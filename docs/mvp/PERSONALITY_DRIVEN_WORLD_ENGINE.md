# AI-PET-WORLD 人格驱动规则世界引擎设计文档

> 文档版本：v1.0  
> 所属系统：AI-PET-WORLD 第二核心系统  
> 系统名称：Personality-Driven Rule-Based World Simulation Engine  
> 中文名称：人格驱动规则世界模拟引擎

---

## 1. 核心定义

AI-PET-WORLD 的世界不是一张预先画好的地图，也不是随机程序生成地图。

它的本质是：

```text
玩家生命信息
→ 管家人格
→ 行为意图
→ 世界规则验证
→ 世界结构变化
→ Renderer 绘制结果
```

因此，AI-PET-WORLD 的世界不是“自动随机成长”，而是：

```text
人格驱动的规则世界
```

更准确地说：

```text
世界规则决定“什么能发生”。
管家人格决定“想不想发生”。
生态环境决定“有没有必要发生”。
空间结构决定“在哪里发生”。
世界变化层决定“发生之后留下什么”。
```

---

## 2. 为什么这套系统不是传统 Procedural Generation

传统程序生成世界通常是：

```text
Seed
→ Noise
→ Terrain
→ Object Placement
→ Renderer
```

AI-PET-WORLD 不是这种路线。

AI-PET-WORLD 的生成源头不是随机种子，而是玩家生命信息生成出的管家人格。世界是否变化、变化快慢、变化方向，都由管家人格、宠物状态、生态环境和世界规则共同决定。

因此它不是：

```text
Random Procedural World
```

而是：

```text
Personality-Driven Rule-Based World Simulation
```

---

## 3. 世界引擎总结构

AI-PET-WORLD 世界生成引擎分为五个核心层级：

```text
1. 世界规则层        World Rule Layer
2. 世界空间层        Spatial Geometry Layer
3. 世界生态层        Ecology & Environment Layer
4. 行为意图层        Intent System Layer
5. 世界变化层        World Evolution Layer
```

其中：

```text
第 1 层：最固定，属于自然法则与基础约束。
第 2 层：相对稳定，但会因建设、灾害、生态扩张而改变。
第 3 层：持续变化，受天气、物种、资源、时间影响。
第 4 层：由人格和世界状态共同决定，可能发生，也可能不发生。
第 5 层：最终把行为和规则验证后的结果写入世界状态。
```

---

## 4. 第一层：世界规则层（World Rule Layer）

世界规则层定义世界中最基础的自然法则和存在约束。

这一层回答的问题是：

```text
什么能存在？
什么不能存在？
什么条件下允许发生？
```

### 4.1 基础规则示例

```text
树必须生长在土地上。
鱼必须生活在水里。
房屋必须有地基。
地基必须建立在可承重地面上。
道路必须连接有效区域。
沙漠不能自然生成普通树木。
水域会影响周围湿度。
火会影响木头、草地和建筑。
```

### 4.2 世界规则不是地图

世界规则不负责“画地图”。

它只负责判断：

```text
某个对象能不能出现。
某个行为能不能执行。
某个变化是否合法。
```

例如：

```text
管家想种树
→ Planner 找到一个位置
→ Rule Engine 检查当前位置是否为土地
→ 如果是水域，拒绝种树
→ 如果是土地，允许进入后续流程
```

### 4.3 规则矩阵示例

| 对象 | 土地 | 草地 | 水域 | 沙漠 |
|---|---:|---:|---:|---:|
| 树 | 可 | 可 | 不可 | 通常不可 |
| 花 | 可 | 可 | 不可 | 通常不可 |
| 鱼 | 不可 | 不可 | 可 | 不可 |
| 仙人掌 | 不可 | 不可 | 不可 | 可 |
| 房屋地基 | 可 | 可 | 不可 | 视承重而定 |
| 桥 | 不独立成立 | 可连接 | 必须跨越 | 视规则而定 |

## 5. 第二层：世界空间层（Spatial Geometry Layer）

世界空间层定义世界的几何基础。

AI-PET-WORLD 的空间不应被简单理解为 tile 地图，而应以点、线、面为基础。

```text
Point 点
Line 线
Polygon 面
MultiPolygon 多面
```

### 5.1 点 Point

点代表实体锚点或关键位置。

例如：

```text
树干中心
房屋入口
宠物当前位置
孵化器位置
管家站位
```

```ts
type Point = {
  x: number
  y: number
}
```

### 5.2 线 Line

线代表连接、路径、边界或流动方向。

例如：

```text
道路
河流
围栏
墙体
宠物移动路径
```

```ts
type Line = {
  points: Point[]
}
```

### 5.3 面 Polygon

面代表区域、占地范围或不规则结构。

例如：

```text
土地
水域
森林
建筑地基
房屋占地
宠物活动区域
```

```ts
type Polygon = {
  points: Point[]
}
```

### 5.4 不规则物体如何处理

不规则物体不应强行塞进方格。

每个实体应包含：

```text
anchor point       锚点
footprint polygon  占地形状
collision polygon  碰撞形状
support polygon    支撑形状
influence polygon  影响范围
```

例如一棵树：

```text
树干 = point
树冠 = polygon
根系 = polygon
阴影 = polygon
影响区 = polygon
```

例如一个房子：

```text
地基 = polygon
墙体 = line / polygon
入口 = point
屋顶 = polygon
内部空间 = polygon
碰撞区域 = polygon
```

## 6. 第三层：世界生态层（Ecology & Environment Layer）

世界生态层定义物种、物质、资源、环境和生态循环。

这一层不是固定的，它会随着时间、天气、物种行为和世界变化持续变化。

### 6.1 生态层包含内容

```text
地形：土地、水域、沙地、森林、石地
环境：湿度、温度、肥力、坡度、光照
物种：植物、动物、宠物、微生态
物质：木材、石头、水、食物、建材
生态关系：捕食、生长、消耗、繁殖、迁徙
```

### 6.2 生态影响示例

```text
雨水增加
→ 土地湿度上升
→ 草地扩张
→ 花草更容易生长
```

```text
干旱持续
→ 水域缩小
→ 鱼减少
→ 水边植物减少
```

```text
树木增多
→ 森林区域扩大
→ 小动物出现概率上升
→ 管家可能产生整理、保护或开辟路径的意图
```

## 7. 第四层：行为意图层（Intent System Layer）

行为意图层是 AI-PET-WORLD 和传统世界生成系统最大的区别。

世界不会自己无条件成长。

世界是否变化，取决于：

```text
管家人格
宠物状态
生态环境
天气季节
资源物质
当前世界结构
```

### 7.1 管家人格决定“想不想做”

并不是所有管家都会建设世界。

有的管家会积极建设：

```text
修路
建房
种树
扩建
整理区域
```

有的管家可能只是维护：

```text
清理
修复
照顾宠物
维持现状
```

有的管家可能长期不建设：

```text
观察
陪伴
等待
停滞
```

甚至有些人格可能偏向破坏或重构：

```text
拆除
改造
重建
改变地形
```

### 7.2 意图不是必然发生

意图产生应是概率性和状态性的。

```text
IntentScore = PersonalityBias
            + EnvironmentNeed
            + PetNeed
            + ResourceAvailability
            + WeatherModifier
            + MemoryModifier
            - Inertia / Laziness / Avoidance
```

当评分超过阈值时，才生成意图。

如果评分不足：

```text
什么都不发生。
```

这意味着：

```text
有些玩家的世界会快速成长。
有些玩家的世界会缓慢成长。
有些玩家的世界可能长期停滞。
```

这不是 bug，而是人格差异的结果。

## 8. 第五层：世界变化层（World Evolution Layer）

世界变化层负责把通过验证的意图写入世界。

它不直接听从管家意图，而是必须经过规则验证。

完整流程：

```text
Intent
→ Planner
→ Rule Validator
→ World Diff
→ World State
```

### 8.1 世界变化类型

```text
GeometryDiff    几何变化，例如新增地基 polygon、道路 line
EntityDiff      实体变化，例如新增树、房屋、鱼、管家设施
EcologyDiff     生态变化，例如草地扩张、水域缩小、森林增加
ConstructionDiff 建设变化，例如地基 → 框架 → 墙体 → 屋顶
StateDiff       状态变化，例如资源减少、湿度上升、宠物关系变化
```

### 8.2 房屋建设示例

```text
管家产生：想建一个小屋
↓
Planner 规划地基 polygon
↓
Rule Validator 检查土地承重、水域重叠、入口连通
↓
通过后生成 FoundationDiff
↓
WorldState 新增地基
↓
后续 Tick 中根据资源和管家行动推导：
地基 → 框架 → 墙体 → 屋顶 → 完成
```

## 9. 管家人格与世界生成的关系

AI-PET-WORLD 的世界不是单纯由规则生成，而是由管家人格推动。

```text
玩家生命信息
→ 命理人格核心
→ 管家人格
→ 行为倾向
→ 意图产生概率
→ 世界变化方向
```

当前人格核心阶段：

```text
14 主星
+ 24 组合星
→ 五维人格映射
→ 管家行为倾向
```

未来人格核心会继续加入：

```text
辅星
杂曜
四化
宫位
格局
流年 / 流月 / 流日
```

因此，当前只是第一层人格驱动，后续会不断细分。

重要结论：

```text
世界变化不是时间驱动。
世界变化是人格 + 状态 + 规则共同驱动。
```

## 10. Renderer 的职责边界

Renderer 不创造世界。

Renderer 只负责读取 WorldState 并绘制结果。

Renderer 输入：

```text
WorldState
GeometryState
EntityState
EcologyState
ConstructionState
```

Renderer 输出：

```text
用户看到的世界画面
```

Renderer 不能：

```text
决定世界生成
决定管家行为
决定建筑是否出现
决定树能不能长
绕过规则直接摆素材
把世界做成一张背景图
```

Renderer 应该：

```text
点 → 画实体
线 → 画道路 / 河流 / 围栏
面 → 画地块 / 湖泊 / 森林 / 建筑地基
阶段 → 画地基 / 框架 / 完成状态
状态 → 画湿度、阴影、磨损、成长痕迹
```

## 12. 核心循环

```text
管家人格
↓
是否产生意图
↓
世界状态刺激：天气 / 物种 / 资源 / 宠物
↓
意图评分
↓
规划结构
↓
世界规则验证
↓
世界发生变化
↓
新世界状态
↓
反过来影响下一次意图
```

这个循环意味着：

```text
世界不是单向生成。
世界是长期反馈系统。
```

## 13. 当前 MVP 应采用的阶段策略

当前阶段不应继续以“贴图 Renderer”为核心。

正确顺序应为：

```text
1. 固定世界规则协议
2. 固定点线面空间协议
3. 固定实体 footprint / collision / support / influence 协议
4. 固定 Intent → Plan → Validate → Diff → WorldState 流程
5. 再做 Renderer
```

当前 Renderer 中出现贴图感的问题，本质不是美术问题，而是世界生成协议还没有完成。

必须先完成：

```text
World Rule Layer
Spatial Geometry Layer
Ecology & Environment Layer
Intent Evaluation Layer
World Evolution Layer
```

再让 Renderer 表现结果。

## 14. AI-PET-WORLD 的第二核心内容

AI-PET-WORLD 的第一核心：

```text
命理人格系统
```

AI-PET-WORLD 的第二核心：

```text
人格驱动规则世界模拟引擎
```

两者关系：

```text
命理人格系统决定生命倾向。
规则世界引擎决定世界能如何被改变。
管家人格把两者连接起来。
```

最终产品定义：

```text
AI-PET-WORLD 是一个由人格驱动、规则约束、生态反馈、长期演化的 AI 生命世界。
```
