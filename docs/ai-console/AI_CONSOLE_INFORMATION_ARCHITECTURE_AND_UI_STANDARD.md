# AI控制台信息架构与专业UI标准

更新时间：2026-08-30 12:26:57 +08:00

状态：active-normative-target

文档版本：`AI-CONSOLE-IA-UI-1.7`

Codex等外部执行智能体不得超出当前用户任务范围；本地程序在生效业务、安全和机器合同内自主运行，不从聊天或本句推导逐步Owner审批。

## 1. 文档职责

本文定义路由层级、Frame嵌套关系、桌面控制台布局、视觉语言、交互状态、响应式和无障碍要求。任何UI实现必须以本标准为准。

## 2. 信息架构

```text
/ai-console                              平台一级总览
├─ /tasks                               AP-01模块总览
│  └─ /tasks/{workspace}                二级工作页
├─ /capabilities
├─ /training
├─ /reviews
├─ /data
├─ /runtime
├─ /evidence
├─ /system
├─ /archive
└─ /control
```

一级目录必须直接进入对应模块总览；二级目录进入真实稳定路由，不使用查询参数或旧页面作为替代入口。

## 3. Frame层级硬性标准

桌面端必须清楚呈现以下三个层级：

1. `ApplicationShell`：最大的主体Frame，由固定顶部栏、固定左侧目录、工作区、上下文区和状态栏组成。
2. `Framework`：工作区中的业务大Frame，共四个，拥有独立编号、标题、职责说明和平面标识。
3. `ModuleFrame`：位于所属Framework内部的小Frame，显示模块身份、职责、二级目录和稳定入口。

禁止形式：

- 把十个模块平铺成无归属卡片墙；
- 用一个统一大边框包住所有模块却不显示四个Framework边界；
- ModuleFrame与Framework边框共线，导致用户无法看出父子层级；
- 用阴影、圆角和营销式大卡片代替控制台结构；
- 在顶部放置跳转旧训练页面的高亮按钮。

## 4. 桌面布局

| 区域 | 标准 |
|---|---|
| Topbar | 高度约86px，固定；只显示平台品牌和运行上下文，不放旧系统快捷入口 |
| PrimaryNavigation | 宽度约232px，固定；自身可滚动 |
| Workspace | 主内容区，独立纵向滚动，禁止带动整个文档根滚动 |
| ContextRail | 宽度约300px，显示能力域、数据基础和当前上下文 |
| LiveObservabilityBar | 高度约50px，固定在主体工作区下方；持续显示CPU、内存、GPU、显存和训练摘要，展开抽屉不改变路由 |
| Statusbar | 高度约38px，固定显示连接状态和当前路由 |

## 5. 大Frame与小Frame视觉规则

### 5.1 外层大Frame

- 使用明确的强边框、独立背景和12至16px内边距。
- Frame Header与Frame Body必须分区。
- Header显示`FRAME-01`至`FRAME-04`、中英文名称、职责和平面。
- Frame Body必须与外部背景留出空间，形成可见容器边界。

### 5.2 内层ModuleFrame

- 必须完整位于Frame Body内，并与父Frame边框保持至少10px间距。
- 多模块Frame使用有间距的两列网格，不使用相邻单元格共边的表格效果。
- Module Header、职责、二级目录和入口Footer分区。
- 观察模块使用青蓝状态，控制模块使用琥珀状态；颜色不是唯一状态表达。

## 6. 视觉语言

- 风格：本地工程控制台、克制、结构化、高信息密度。
- 形状：直角或极小圆角，避免消费级卡片风格。
- 字体：标题使用清晰无衬线，机器字段和身份使用等宽字体。
- 颜色：默认使用暖灰白Canvas、白色主体内容和冷灰白导航/字段层承担结构；暗色不是平台基底。模块身份色只用于定位，绿色表示连接或成功，琥珀表示控制边界，红色只用于失败或紧急状态。
- 间距：父子容器必须通过边框、背景和留白三种信号共同表达。

### 6.1 V19明亮企业控制台色彩系统

颜色必须按职责使用，不得把“AI”理解为全页面统一青色：

| 色彩角色 | 使用范围 |
|---|---|
| 明亮中性层级 | 暖灰白Canvas、白色ApplicationShell和工作区、冷灰白导航、嵌套面板与字段背景；通过克制的明度、边框和留白表达父子层级 |
| 模块身份色 | AP-01至AP-10的活动导航、Hero编号、Frame关键线和少量背景Wash；不得大面积填满内容区 |
| Frame身份色 | FRAME-01蓝紫、FRAME-02青绿、FRAME-03靛蓝、FRAME-04琥珀；只帮助识别业务边界 |
| 状态色 | 绿色表示连接/成功，金色表示等待/未知，红色表示失败/紧急，琥珀表示人工控制边界 |
| 数据通道色 | CPU蓝、内存紫、GPU青绿、显存金、温度红；同一指标在状态条、仪表和趋势中保持一致 |

颜色不能成为唯一信息载体；模块名称、状态文字、数值、边框和图形仍必须同时存在。所有页面必须从`ai-console-theme.module.css`继承Token，不得在组件中重新建立互相冲突的调色板。

## 7. 二级页面标准

1. 复用同一ApplicationShell。
2. 顶部和左侧目录保持固定，中部内容独立滚动。
3. 模块二级目录位于Hero下方，当前页有明确状态。
4. 页面内容按业务使用七类专业呈现，不复制同一空卡片模板。
5. 页面合同状态和权威数据状态必须同时可见且语义分离。
6. 已登记控制执行器的结果区必须显示命令终态、命令身份、证据与回执摘要；持久复核使用完整命令身份精确查询，显示服务端完整性状态和固定逻辑路径，不显示通过目录扫描生成的历史列表。
7. AP-07证据浏览默认进入“正式证据记录”，以只读检索视图显示证据身份、类型、逻辑路径和完整性状态；记录详情提供内容摘要、来源绑定、登记事务和哈希链。只有精确身份API复核通过的JSON/JSONL可以进入限长等宽文本检查区，SQLite不展开、不下载、不执行。
8. AP-07任务胶囊使用实体登记视图；“任务目标”“输入与能力”“执行摘要”“终态与边界”必须分别选择对应的四个主字段，记录详情保留全部严格字段。正式空库显示“已连接、当前0条”，不得用示例任务填满页面。
9. AP-07政策边界默认进入“正式边界报告”，报告矩阵只展示受验证的实际阻断；“边界规则目录”等其余页签显示产品合同。空正式库必须显示“已连接、当前0条”，不得把六条规则渲染成六条实际报告。
10. AP-01当前任务、队列和任务记录必须使用同一任务登记来源；真实空库显示已连接。活动执行在执行器未接入时显示部分连接且不显示伪造进程、心跳或进度。AP-10任务控制必须把三种已启用登记操作与仍禁用的启动、暂停、恢复命令同时明确标识。
11. AP-02候选、当前门禁与资格结果使用V12能力生命周期来源；发布列表联合V15激活登记显示活动、被取代和未激活状态，资格图与迁移门禁合同必须和实际记录分层。AP-10能力控制按“候选→资格→非活动发布→合格发布激活”四个内部小Frame排列；停用、回退和迁移裁决仍禁用。
12. AP-03模型结构与训练计划必须使用同一V13训练设计来源；AP-10训练控制应按“模型结构→训练计划”两个内部小Frame排列。模型是计划的前置依赖；训练启动、暂停、恢复、停止和资源窗口命令仍必须以禁用合同独立呈现。
13. AP-04审核合同、审核结果和失败分类必须使用同一V14审核裁决来源；AP-10验证控制在主登记核验Frame之后，以“冻结审核合同→机器观测终态”两个内部小Frame排列。观测Frame只能输入机器观测，不得提供人工通过/失败选择；当前验证、证据查看、验证启动和审核重跑保持独立且不得伪造接入。
14. AP-06候选与RuntimeFrame必须使用V15运行发布来源，世界运行必须只使用V16世界控制来源；真实空库显示`connected · 0`，不得回退旧World Runtime。AP-10世界控制在“现有视觉制品候选登记→机器审核通过的正式未消费Frame登记”之后，继续以“正式Frame消费→发布/回退/视觉控制”两个内部小Frame排列。消费只能选择V15正式未消费Frame；控制必须同时显示发布状态、世界修订和合法祖先目标，并明确全部操作只写新平台登记库。
15. 所有页面必须复用同一个`LiveObservabilityBar`。训练过程中，用户在任务、数据、审核或证据页面也能展开资源和训练摘要；展开行为不得跳转、遮断键盘焦点或改变业务查询上下文。
16. AP-08资源总览采用四个主资源仪表、温度/功耗/磁盘事实带、实时趋势和进程表；AP-03训练总览采用正式训练上报Frame、Loss趋势、资源仪表和独立进程表。进程表必须写明“不等于正式Run”。

## 8. 响应式与无障碍

- 1220px以下允许ContextRail进入工作区下方，但仍属于ApplicationShell内容。
- 860px以下转为自然文档流，避免固定区域挤压触控内容。
- 所有链接、视图按钮、搜索框和筛选器必须可键盘操作并有可见焦点。
- 状态不能只靠颜色表达；必须同时提供文字。
- 页面不得出现横向文档溢出。

## 9. 专业标准依据与项目裁决

本项目采用下列公开专业标准的原则，但不直接引入其组件库或品牌视觉：

| 标准 | 采用原则 | 项目裁决 |
|---|---|---|
| [IBM Carbon UI Shell](https://carbondesignsystem.com/components/UI-shell-left-panel/usage/) | Header、左侧导航、右侧面板共同构成跨页面持久化产品壳 | 顶部、左侧目录和状态栏属于ApplicationShell；内容页不得重新发明壳层 |
| [IBM Carbon 2x Grid](https://carbondesignsystem.com/elements/2x-grid/usage/) | 网格、关键对齐线、固定面板与流动内容共同建立结构秩序 | 使用统一间距倍数、清晰关键线和父子容器内缩，不使用营销卡片瀑布流 |
| [IBM Carbon Color](https://carbondesignsystem.com/elements/color/overview/) | 中性色承担大部分界面，White与Gray 10等明亮层级可组织容器；颜色以角色Token管理并克制使用 | 默认采用明亮中性层级，模块色和状态色只负责身份与事实，不把暗色当作“AI控制台”的必然风格 |
| [Grafana Saga](https://grafana.com/developers/saga/about/overview/) | 可观测性产品使用共享视觉语言和可重复模式保持跨仪表盘一致性 | 固定CPU、内存、GPU、显存、温度的跨页面数据通道，不让所有曲线使用同一颜色 |
| [W3C ARIA Landmark Regions](https://www.w3.org/WAI/ARIA/apg/practices/landmark-regions/) | 页面应有唯一主内容地标；多个导航必须有独立可访问名称 | 每页只保留一个`main`；平台导航、二级导航、面包屑和页内导航分别命名 |
| [USWDS Side Navigation](https://designsystem.digital.gov/components/side-navigation/) | 侧边导航表达稳定层级、当前页面和父子关系 | 左侧只承担一级模块，模块内二级页面使用横向目录，避免无限加深左侧树 |

上述标准只提供布局、语义和交互依据。AI控制台的业务身份、状态字段、数据来源和安全边界仍以本项目正式文档为唯一权威。

## 10. UI验收清单

1. 顶部不存在“训练监控”或任何旧页面快捷入口。
2. 训练控制的两个登记小Frame位于AP-10工作区内部，不改变固定顶部、左侧主体目录、右侧能力栏和底部状态栏。
3. 左侧AP-01至AP-10均进入`/ai-console/*`。
4. 首屏能够识别外层Framework与内层ModuleFrame父子关系。
5. 父Frame和子Frame之间存在独立边框、背景与间距。
6. 文档根不滚动，工作区和目录独立滚动。
7. 1920、1440、1280和移动宽度无布局断裂。
8. 页面存在唯一`main`地标、命名导航和键盘可见焦点。
9. 任务胶囊页四个业务视图均显示`CONNECTED`和受验证空库；未来出现正式记录时，视图列必须随业务范围切换并可进入完整记录详情。
10. 政策边界页默认报告视图显示`CONNECTED`和受验证空库；切换规则页签后显示六类合同，且报告身份保持空值。
11. 自动结构检查必须阻止任何旧页面路由、旧页面组件或旧页面API进入新控制台源码。
12. 控制回执复核输入必须具备可访问名称、64位身份格式约束、查询中和失败关闭文字状态；完整性不能只用颜色表达。
13. 正式证据记录必须使用检索结果、只读详情和独立内容检查面板；文本检查必须显示完整或已截断状态，二进制模式必须明确说明只显示元数据，任何内容均不得作为HTML渲染或执行。
14. 事务“文件与事件”“SQLite一致性”沿用拓扑视图，但记录详情必须显示四类证据身份和文件、事件、SQLite、索引、跨表面五项文字状态；不得只用颜色表示一致性。
15. AP-10世界控制必须显示执行器、全局登记修订、世界/状态/命令数量和`new_ai_console_only`执行边界；空库时消费与控制按钮禁用，不生成示例世界。暂停、恢复、回退和冻结按钮必须位于外层控制工作区中的同一内层操作Frame，并通过文字区分可用、禁用和失败关闭。
16. AP-06世界运行的表格字段必须来自V16状态字典，包括世界状态修订、活动Frame、发布控制、视觉更新与世界修订；UI源码和网络请求不得出现`/ai-painter-progress`、`/api/ai-painter`或旧World Runtime读取路径。
17. 任务控制页必须显示执行器、登记修订、任务总数和执行边界；空队列禁用目标操作。任务登记表单必须要求目标、能力域和1至9优先级，所有写入状态必须包含文字终态、身份与摘要。
18. 能力控制页必须显示执行器、登记修订、候选/资格/发布数量和执行边界；空候选禁用资格与发布操作。资格表单必须显示由服务端状态决定的下一门禁并要求64位证据摘要，发布表单必须明确结果为非活动发布。
19. 训练控制页必须显示执行器、登记修订、模型/计划数量和执行边界；无模型时禁用计划登记。两个登记Frame分别核对模型内容身份和计划依赖，并明确所有训练运行命令禁用。
20. 验证控制页必须显示审核执行器、登记修订、合同/结果数量和服务端裁决边界；无冻结合同时禁用机器观测登记。审核结果预判只用于展示冻结阈值计算，最终终态必须由服务端重新计算并返回不可变回执。
21. 全局实时条在1920、1440、1280和移动宽度不得造成横向溢出；860px以下进入粘性自然流，展开抽屉限制在当前视口内。
22. 实时连接、失败和未上报状态必须同时使用文字与颜色；实时数值必须附带精确到毫秒的采样完成时间、快照年龄或连接状态。
23. 一级总览、十个模块、52个工作页与实时观察面必须复用同一语义色Token；Frame、模块、状态和数据通道能够区分，但不得出现大面积彩虹卡片、渐变营销背景或只靠颜色表达状态。
24. 默认主题必须整体明亮：Canvas、顶部、左侧目录、主工作区、右侧上下文、底部实时条及二级内部组件均不得使用暗色作为基础表面；七类二级呈现中的输入、命令节点、边界提示和证据检查区必须保持浅色可读层级。
25. 折叠实时条必须持续显示采样序号与年龄；展开条及AP-03/AP-08仪表盘必须显示`HH:mm:ss.SSS`完成时间、采样耗时、HTTP往返耗时和GPU通道年龄。界面必须标明250毫秒是目标刷新间隔，毫秒时间合同不等于硬件计数器每1毫秒更新。
26. `/ai-painter-progress`及其任意旧子路径不得渲染旧应用壳或旧工作区；兼容入口必须直接永久重定向到`/ai-console`，且重定向过程不读取查询参数、训练证据或旧API。
27. 一级页当前执行面板以及AP-01/AP-03/AP-04相关工作页必须显示同一登记修订和Run；连接中、受验证、不可用三种状态必须有文字，不得以静态`CONNECTED`、默认0或历史选择伪装实时事实。
