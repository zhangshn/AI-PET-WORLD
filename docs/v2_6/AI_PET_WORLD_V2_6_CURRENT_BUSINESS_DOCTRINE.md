# AI-PET-WORLD V2.6｜当前业务原则

> 本文档用于锁定当前业务理解，避免历史设定、旧孵化器链条、网页卡片主页、Debug Composer 或传统宠物养成思路污染后续开发。
>
> 当前业务以“自主 AI 世界”为核心。所有未来扩展都必须服从这一原则。

---

## 1. 核心一句话

AI-PET-WORLD 不是传统宠物养成游戏，而是一个由 AI 管家和未来 AI 生命自主推动建设、联络、选择、发展和演化的像素生命世界。

用户不是直接操控者，而是世界源头、观察者与联络者。

---

## 2. 用户与世界的关系

用户创建的是一个世界，不是直接领取一只宠物。

创建世界后，系统生成 runtime save、家园空间、资源状态、世界事实、管家与基础演化链路。

用户不通过点击直接命令世界成长，而是通过观察、P-Phone 联络、长期关系和未来系统入口影响世界。

---

## 3. 管家是核心自主行动者

管家不是 UI 助手，也不是网页客服。

管家是世界内的自主 AI 主体，是家园建设者、联络者、判断者、记录者、研发者和未来文明推动者。

管家可以自主：

- 观察世界。
- 整理家园。
- 建设房屋与设施。
- 维护环境。
- 留下行为痕迹。
- 形成记忆种子。
- 判断世界是否成熟。
- 选择是否去小镇。
- 选择是否了解领养中心。
- 选择是否领养宠物。
- 选择不领养宠物。
- 通过 P-Phone 与用户、其他管家、未来世界系统联络。
- 在未来研发 P-Phone App 或世界能力。

管家的行为必须是 AI 驱动的自主行为，而不是玩家按钮脚本。

---

## 4. 宠物的正确位置

宠物不是 create-world 默认产物。

宠物不是 UI 占位物。

宠物不是旧孵化器 / 胚胎 / hatch 链条。

宠物也不是被系统为了让画面完整而自动生成的 actor。

宠物未来应该作为正式世界事实进入，例如：

```txt
世界成熟
→ 管家产生自主判断
→ 管家可能前往小镇
→ 管家可能接触领养中心
→ 管家可能选择领养
→ 也可能选择不领养
→ 若领养成立，宠物作为正式生命事实进入世界
```

这意味着：

```txt
没有正式生命事实来源，就不能出现宠物 actor。
```

但这不代表宠物被废弃。宠物仍然是 AI-PET-WORLD 的重要未来生命主体，只是不能在当前阶段默认生成。

---

## 5. 小镇 / 公园 / 医院 / 多用户的正确位置

小镇、公园、医院、多用户不是废弃内容。

它们是后续阶段内容，但它们的生成和运行方式不能是传统功能菜单式系统。

未来这些内容应该由 AI 管家和世界自主发展推动：

- 小镇可以由多个管家、世界阶段、资源状态、建设倾向和事件积累共同形成。
- 小镇中可以存在领养中心。
- 管家可以自主选择是否去小镇。
- 管家可以自主选择是否接触领养中心。
- 管家可以自主选择是否领养宠物。
- 公园、医院、商店、公共设施等都应是世界和管家共同演化出来的系统，而不是玩家手动摆放的网页功能卡片。
- 多用户世界应围绕管家、世界、P-Phone、关系、事件、自治建设和通信展开。

这些内容后置，不是因为不重要，而是因为当前必须先把自主世界底座、事实链路、验算库和正式画图算法打稳。

---

## 6. P-Phone 的正确位置

P-Phone 不是旧网页卡片。

M11 阶段删除的是旧 `/world` 主页里的网页卡片式 P-Phone 展示，不是删除 P-Phone 这个核心设定。

P-Phone 是 AI-PET-WORLD 未来的正式通信与系统入口，设定应接近真实手机：

- 电话。
- 短信。
- 语音。
- 通知。
- 联系人。
- 世界日志。
- 管家消息。
- 管家与用户联络。
- 管家与其他管家联络。
- 小镇 / 领养中心 / 公共系统联络。
- App 生态。

未来部分 App 不应该全部由开发者写死，而可以逐步发展成由管家自主研发、安装、改造或使用的系统能力。

P-Phone 是用户和管家之间的重要桥梁，也是未来多管家、多世界、多系统通信的入口。

---

## 7. 自主 AI 是核心

AI-PET-WORLD 的核心不是“做更多功能”。

核心是：

```txt
有灵魂的 AI
自主选择
自主建设
自主联络
自主研发
自主形成世界关系
自主推动文明倾向
```

任何功能只要变成纯按钮、纯菜单、纯任务脚本，都偏离产品核心。

未来正式功能应优先回答：

- 这个行为是否由管家或 AI 生命自主产生？
- 这个结果是否进入世界事实链路？
- 这个变化是否可追踪、可解释、可被记忆？
- 用户是否仍然是观察者 / 联络者，而不是直接操控者？
- P-Phone 是否作为自然通信入口，而不是普通网页卡片？

---

## 8. 当前阶段边界

当前阶段仍然不做：

- M8 / M9 / M10。
- 宠物学习。
- 小镇正式运行。
- 公园正式运行。
- 医院正式运行。
- 多用户正式运行。
- 网页卡片主页。
- 旧 `/world` 画面恢复。
- Debug Composer 进入正式 `/world`。
- 旧孵化器 / embryo / hatch / incubator 业务链条。

但这些后置内容的未来方向必须按本文档理解：

```txt
不是功能菜单扩展，
而是管家和世界自主发展出来的 AI 生态。
```

---

## 9. 当前开发优先级

当前继续推进：

```txt
核心资源库 / 验算库
→ 正式画图算法重整
→ 端游式 /world 主世界恢复
```

在正式 `/world` 恢复前，必须先保证：

- 世界事实链路干净。
- 历史旧链路残留清理干净。
- P-Phone 不再被误解为旧网页卡片。
- 宠物不默认生成，但未来可通过正式自主链路进入。
- 小镇 / 领养中心 / 公园 / 医院 / 多用户被理解为后续自主世界系统，而不是废弃项。
