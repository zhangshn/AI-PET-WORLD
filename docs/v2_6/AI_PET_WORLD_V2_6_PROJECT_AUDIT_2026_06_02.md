# AI-PET-WORLD V2.6｜项目审查记录｜2026-06-02

## 1. 当前业务定义

```txt
用户注册
→ 输入出生年月日等生命信息
→ 紫微斗数映射管家初始灵魂与人格倾向
→ 创建个人世界
→ 管家和世界在规则约束下自主运行
→ 用户通过 P-Phone 沟通和提出建议
→ 管家自主接受、延后、调整或拒绝建议
→ 未来不同玩家的管家共同建设小镇与城市
```

玩家是世界源头和长期关系参与者，不是直接操作者。紫微斗数是管家的长期人格核心，不是前台标签。

## 2. 已有工程基础

- 紫微斗数、八字、人格转译与管家自主意识相关模块已经存在。
- 世界空间、资源、痕迹、时间线、建设意图、规则验证和只读投影链路已经存在。
- `WorldViewModel → PixelWorldView → PixelWorldPixelBufferFrame → PixiJS` 已接入正式 `/world`。
- P-Phone 只读投影与“管家不是按钮执行器”的业务边界已经有文档基础。

## 3. 当前真实卡点

当前卡点不是“完全没有画面”，而是“画面仍然停留在工程预览”。

PixiJS renderer 已经存在，但当前主要绘制矩形色块。正式画面仍缺少：

- 对象级像素配方：树、草、石头、昆虫、建筑细节。
- 管家 Sprite：外形、动作、朝向、状态与人格差异。
- 建筑生长表现：从建设事实到阶段变化的可视化。
- 生态变化表现：痕迹、季节、时间、维护和长期演化。
- 产品化 UI：正式 `/world` 仍有工程状态卡片，需要收口为端游式主世界和轻量 Overlay。

## 4. 文档审查结论

原文档总体方向正确，但存在两类偏差：

- 缺少硬规则：注册后生命信息输入、紫微斗数作为管家灵魂、建议可被管家拒绝、未来小镇和城市由不同玩家管家共同建设。
- 进度滞后：部分文档仍描述 `/world` cleared 和 renderer 尚未开始，实际代码已接入 PixiJS 只读入口。

本次已经更新正式原则、文档入口和模块进度，并把旧 M11 handoff 标记为历史交接记录。
