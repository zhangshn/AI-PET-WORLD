# AI-PET-WORLD V2.6｜完整业务架构总图（强化版）

> 本大纲由同名 XMind 导出，用于快速核对结构。正式文件以 XMind 为准。
> 本版已补充：正式像素主世界绘制方案、Pixel Scene Composer 的业务定位、WorldViewModel → PixelWorldView 落地边界。

- AI-PET-WORLD V2.6｜完整业务架构总图
  - 0. 总原则｜世界由规则、坐标、生态、生命、痕迹和时间线共同生成
    - 文档定位：业务架构思维导图，不是代码架构、接口文档、文件目录或 Debug 说明
    - 产品本质：AI 自主世界 + 虚拟生命 + 命理人格 + 时间线演化 + 痕迹沉淀 + 长期关系
    - 用户定位：用户是世界源头、观察者与轻影响者，不是直接控制者
    - 管家定位：管家是用户生命信息在世界中的自主意识管理者，拥有初始人格、记忆、学习和长期成长
    - 宠物定位：宠物是独立生命，不是默认资产；未来进入世界后拥有出生人格、记忆、学习和成长
    - 世界定位：世界不是背景板，而是拥有状态、历史、痕迹、记忆和学习能力的演化环境
    - 空间底座：二维 / 三维坐标、区域、地块属性、对象占用、边界、可通行性与移动成本
    - 核心修正：不设置独立移动通道架构，不把移动通道作为世界生成前提；所有长期移动结果统一归入痕迹体系
    - 痕迹定位：痕迹是世界记忆的外在形式，也是学习、变化和表现的核心入口
    - 核心公式：世界事实 + 世界规则 + 生命人格 + 行为意图 + 痕迹沉淀 + 时间线 + 学习反馈 = AI 自主世界
    - 正式表现红线：/world 正式入口必须是像素主世界，不承载 SVG、CSS 几何图层、procedural renderer、Debug 卡片或工程验收面板
    - Debug 隔离原则：所有审计、手动 Tick、SVG 预览、几何诊断、内部字段和工程日志统一进入 /world-debug 或内部测试页
  - 1. 产品战略与业务定位架构
    - 一句话定义：AI-PET-WORLD 是一个由用户生命信息启动、由 AI 管家自主意识管理、由规则生态世界承载、由时间线和痕迹持续演化的 AI 虚拟生命世界
    - 战略定位
      - 不是传统养宠游戏：不以点击喂养、收菜、任务清单作为核心
      - 不是静态像素地图：地图只是表现层，世界本体必须具备事实、规则、变化、痕迹与记忆
      - 不是命理展示工具：命理是生命个体差异生成规则资产，不是给用户看的表层标签
      - 不是单纯 AI 聊天：对话只是联系方式，核心是世界持续运行与生命行为
      - 不是纯随机生成：随机必须可解释、可复现、受世界规则约束
      - 不是 SVG / CSS 图层 Demo：矢量几何、CSS 拼贴、procedural renderer 只能作为 Debug 或历史验证，不是正式主世界
      - 不是卡片仪表盘：正式体验不能靠 Hero、状态卡、资源表和审计面板来代替世界本身
    - 用户价值主张
      - 长期陪伴：用户看到一个世界随着时间和生命关系慢慢成长
      - 个体差异：每个管家和宠物因为生命信息、人格、经历和记忆不同而不同
      - 低操作高情感：用户不需要频繁操作，却能持续获得世界回应和情绪回报
      - 可观察成长：树、草、建筑、生命、关系、痕迹都应随时间变化
      - 可解释自主：管家行为和世界变化可以通过业务解释被用户理解
    - 商业定位
      - 基础订阅：持续运行世界、保存记忆、维持管家关系、长期世界演化
      - 高级订阅：更多世界容量、更丰富记忆、更深人格演化、更复杂生态和关系
      - 事件经济：特殊事件、节日、世界阶段、生命关系、小镇机构、跨世界互动
      - 长期资产：世界历史、生命记忆、关系、痕迹、家园成长可成为用户长期价值资产
  - 2. 完整世界图生成核心逻辑｜不是坐标直接画图，而是规则生成世界
    - 核心结论：完整世界图不是靠坐标直接画出来；坐标只是定位底座，真正生成图的是世界生成算法群
    - 世界生成算法群
      - 世界种子算法：形成稳定世界基因，保证同一世界基础分布可复现、不乱跳
      - 世界事实算法：读取当前世界已有事实，包括地貌、资源、生态、对象、生命、事件、痕迹、时间阶段
      - 世界规则算法：判断什么允许出现、什么不能出现、什么更多、什么更少、什么需要避让或验证
      - 空间布局算法：用二维 / 三维坐标、区域、边界、对象占用、可通行性和移动成本安排对象落位
      - 生态分布算法：根据地貌、湿度、生态健康、自然生长、空间压力生成草、树、石头、花、小生态
      - 对象生成算法：决定单个对象的形态，例如树的年龄、成长、健康、湿度、地貌共同决定外观
      - 痕迹沉淀算法：把行为、生态、建设、关系和时间留下的影响沉淀到坐标、区域和对象上
      - 行为影响算法：管家、宠物和未来生命行动后，通过规则验证改变世界状态或痕迹
      - 学习反馈算法：管家、宠物、世界从记忆、痕迹、结果和反馈中形成经验
      - 视觉表现算法：把事实、规则、状态、生态、痕迹转译成用户能看见的画面
      - 图层合成算法：地面、生态、痕迹、对象、建筑、生命、前景、光照、氛围按层合成
    - 坐标在生成中的角色
      - 坐标负责：对象在哪里、事件在哪里、痕迹在哪里、谁遮挡谁、是否重叠、是否可通行
      - 坐标不负责：为什么这里有树、为什么草变低、为什么区域变荒、为什么管家经过这里
      - 二维坐标：负责世界平面位置
      - 三维 / 层级坐标：负责高度、遮挡、楼层、前后关系、视觉层级
      - 结论：没有坐标，世界无法稳定落位；只有坐标，世界不会自己长出来
    - 正式主世界生成链路：世界事实 + 空间网格 + 痕迹场 + 生命状态 → WorldViewModel → PixelWorldView → Tile / Object / Sprite / Trace Layer
    - AI 出图约束：不能直接让 AI 画一张宠物世界图，必须先给世界事实、区域、生态、痕迹、生命位置、图层规则和禁止项
    - 正式渲染边界：SVG、CSS 几何图层、procedural painter、formal geometry renderer 只能用于内部验证或 /world-debug，不作为 /world 正式渲染底座
    - 2.1 正式像素主世界绘制方案｜从规则组合到 PixelWorldView
      - 本节定位：明确正式 /world 到底如何画，不再把 Debug 画面、SVG、CSS 几何图层或卡片面板误当主世界
      - 画面方向：正式 /world 是 PixelWorldView，不是 SVG 图、CSS 拼贴、procedural renderer 页面、Debug composer 页面或静态截图
      - 昨天 Pixel Scene Composer 的定位
        - /world-debug/pixel-scene-composer 是像素世界组合规则实验室
        - 它验证地面 tile、生态过渡、草簇、树、灌木、石头、花、痕迹和角色占位能否组成完整世界画面
        - 它不写正式世界事实，不推进 runtime Tick，不生成宠物，不是正式 /world
        - 它的成果要沉淀为正式 mapper 和绘制规则，而不是把 Debug 页面原样搬到 /world
      - 正式主世界绘制链路
        - WorldRuntimeSaveRecord + HomeMapState + SpaceGrid + TraceField + ButlerState → WorldViewModel
        - WorldViewModel → PixelWorldView
        - PixelWorldView → Tile Layer / Trace Layer / Object Layer / Sprite Layer / Atmosphere Layer / UI Overlay
      - WorldViewModel 最小职责
        - worldId / tick / canvas / tileSize：定义同一世界在画布中的稳定尺度
        - tiles：由地貌、湿度、生态健康、空间压力、可通行性和移动成本转译而来
        - objects：由 HomeMapState、自然对象事实、建筑事实和生态对象事实转译而来
        - traces：由 TraceField、TraceLifecycle、TraceInfluence、TraceVisualProjection 转译而来
        - actors：由 ButlerState / runtime decision / 生命状态转译而来；宠物未正式入场前不能显示宠物
        - overlays：只保留必要的管家解释、P-Phone 入口和轻状态，不用卡片替代世界
      - PixelWorldView 图层生成顺序
        - 1. Tile Layer：根据地貌、湿度、生态健康、空间压力生成地面像素 tile
        - 2. Trace Layer：根据 TraceField 生成踩踏、裸土、草地压低、维护痕迹、恢复痕迹和等待点
        - 3. Object Layer：根据世界事实生成树、草、石头、花、蘑菇、小生态、建筑和未来设施
        - 4. Sprite Layer：根据生命状态绘制管家主体；未来宠物进入世界后再绘制宠物主体
        - 5. Atmosphere Layer：根据时间线、世界阶段、生态状态表现光照、氛围和季节感
        - 6. UI Overlay：只展示 P-Phone、管家一句话和必要状态，不覆盖主世界画面
      - 每一层怎么画
        - Tile 不是直接按坐标上色，而是由世界事实、地块属性、生态状态和移动成本共同决定 tile 类型和变体
        - Trace 不是装饰，而是行为、生态、建设、关系和时间沉淀后的可持续影响，会参与后续行为和学习
        - Object 不是随机撒点，而是由空间布局、生态分布、对象生成规则和占用验证共同决定落位
        - Sprite 不是默认资产展示，管家来自用户生命信息投射；宠物未来必须经过出生和入场规则
        - Atmosphere 不是背景滤镜，而是时间线、生态健康、世界阶段和长期状态的表现结果
      - 与自主世界的关系
        - 画面不是世界本体，画面是世界事实、规则、痕迹、生命状态和时间线的表现结果
        - 管家意图、世界规则验证、SafeApply、TraceField、MemorySeed 和学习反馈决定世界如何继续变化
        - PixelWorldView 只读 WorldViewModel；世界变化只能来自显式 runtime Tick 和规则验证后的事实更新
      - Debug 隔离边界
        - Pixel Scene Composer、SceneSvg、ProceduralPainter、FormalGeometry、审计卡片、手动 Tick 统一留在 /world-debug
        - /world 正式入口不引用 buildSceneSvg、WorldPainterReadonlyPreview、ProceduralRendererView 或 FormalWorldView
        - Debug 页面可以验证算法，不能直接成为正式产品体验
      - 禁止项
        - 禁止正式 /world 使用 SVG 作为主视觉
        - 禁止使用 CSS 几何图层画世界对象、地块、痕迹或角色
        - 禁止把 /world-debug/pixel-scene-composer 原样搬到 /world
        - 禁止把 buildSceneSvg 或 data:image/svg+xml 作为正式主画面输出
        - 禁止新增宠物事实、独立移动通道、roadGraph、pathGraph 或未验证的建设事实
        - 禁止把 Hero、状态卡、资源表和审计面板当作主世界
      - 下一步落地模块
        - WORLD-VIEWMODEL-PIXEL-MAPPER-00：建立 WorldRuntimeSaveRecord / HomeMapState / SpaceGrid / TraceField → WorldViewModel
        - PIXEL-WORLDVIEW-CANVAS-00：建立正式 PixelWorldView，用 canvas 或后续 PixiJS 绘制 Tile / Object / Sprite / Trace Layer
        - WORLD-DEBUG-ASSET-ISOLATION-00：把 SceneSvg、procedural renderer、FormalGeometry 和审计工具完全隔离到 /world-debug
        - BUTLER-INTENT-TO-WORLD-CHANGE-00：继续自主世界闭环，让管家意图经过规则验证沉淀为事件、痕迹或事实变化
  - 3. 横向八层业务母架构

    - 3.2 生命人格与记忆层｜定义生命如何形成个体差异、记忆与成长
      - 母职责：定义管家、宠物和未来生命体的统一人格算法、角色表达、记忆沉淀、关系成长与学习接口
      - 用户生命信息体系
        - 用户是世界源头，不是直接控制者
        - 用户生命信息用于生成管家初始人格投射
        - 正式 UI 不展示命理术语，只展示转译后的生命差异、行为倾向和管家解释
      - 人格定义模块
        - 命理人格规则体系：紫微斗数 / 命理作为生命个体差异生成规则资产，不作为前台标签
        - 统一生命人格算法：管家、宠物和未来生命共享底层人格算法，不拆两套人格核心
        - 统一人格画像：算法输出 BasePersonalityProfile / Trait Vector / 行为倾向 / 关系倾向 / 节奏偏好
        - 角色输入源
          - 管家输入源：用户生命信息 + 世界种子 + 创建世界上下文
          - 宠物输入源：出生时刻 + 物种 + 初始状态 + 环境 + 世界阶段
          - 未来生命输入源：角色类型 + 出生规则 + 世界上下文
        - 角色人格表达适配
          - 管家表达适配：观察、维护、建设、等待、保护、解释、用户关系、世界管理
          - 宠物表达适配：探索、休息、靠近、回避、舒适区、习惯形成、环境学习
          - 未来生命表达适配：按角色职责转换统一人格画像
        - 管家人格子架构
          - 管家是用户生命信息在世界中的自主意识管理者，不是任务执行器或玩家鼠标
          - 管家人格影响观察风格、维护优先级、建设倾向、等待方式、保护倾向和解释语气
          - 管家人格只能影响行为倾向，不能直接改写世界事实
        - 宠物人格子架构
          - 宠物是独立生命，不是默认资产，不是用户人格复制品
          - 宠物人格影响探索、靠近、回避、休息、舒适区形成和关系建立速度
          - 宠物不说人话，正式表现以动作、位置、节奏、痕迹和管家观察为主
        - 人格成长
          - 初始人格不被覆盖，后天经历只改变表达方式、行为概率、关系倾向和成长路径
          - basePersonality + experienceModifiers + relationshipModifiers + traceLearningModifiers + timelinePhaseModifiers = expressedPersonality
      - 记忆模块
        - 记忆总原则：记忆不是日志，而是会影响后续判断、关系、行为倾向和解释方式的经验资产
        - 共享记忆生命周期：生成 → 合并 → 加权 → 衰减 / 强化 → 影响行为 → 进入解释或表现
        - 管家记忆子架构
          - 短期记忆：最近观察、最近行为、最近异常、最近世界变化
          - 长期记忆：建设经历、维护习惯、风险判断、用户关注对象
          - 关系记忆：用户、宠物、世界对象、未来其他管家的关系记录
          - 空间记忆：常去区域、回避区域、维护区域、重要地点
          - 生态记忆：哪些树需要照顾、哪些区域容易衰退或恢复
          - 情绪记忆：长期事件和关系回应对管家表达方式的影响
        - 宠物记忆子架构
          - 环境熟悉学习：安全、陌生、舒适、异常、常去位置
          - 舒适区域记忆：树下、庭院边缘、家园门口、草地柔软位置
          - 危险区域记忆：空间压力高、异常发生、边界陌生、生态衰退区域
          - 与管家关系记忆：陌生、熟悉、信任、依赖、警惕
          - 与用户关系记忆：通过长期轻影响和管家转达形成安全感，不是点击好感度
          - 行为习惯沉淀：人格、状态、熟悉度、舒适区、危险记忆和痕迹反馈共同形成习惯
        - 记忆与人格表达关系：记忆不能覆盖初始人格，只能改变当前表达、行为倾向、解释方式和关系权重
      - 关系成长与学习接口
        - 管家、宠物、世界的学习结果必须经过世界规则验证
        - 学习以显式规则、记忆权重、痕迹统计和行为结果反馈为主
        - 人格、记忆、关系、痕迹和时间线共同影响后续行为，但不绕过世界事实
    - 3.3 世界规则层｜定义世界如何生成、判断、约束与演化
      - 母职责：决定什么可以发生、什么不能发生、什么如何发生
      - 生成规则
        - 世界初始生成规则
        - 生态对象生成规则
        - 自然对象生命周期规则
        - 区域状态生成规则
        - 痕迹生成规则
      - 约束规则
        - 不能无事实生成正式对象
        - 不能跳过世界验证
        - 不能违反空间边界
        - 不能让人格直接改写世界
        - 不能让学习结果直接成为世界事实
      - 硬规则
        - 不能穿越实体
        - 不能越过封闭边界
        - 不能进入未开放区域
        - 不能让宠物默认进入世界

    - 为什么需要痕迹
      - 坐标只能说明在哪里，痕迹说明这里曾经发生过什么
      - 痕迹可以表达移动、照料、荒废、恢复、关系、时间和记忆
      - 痕迹让世界从静态地图变成带历史的世界
      - 痕迹是管家、宠物和世界学习的重要依据
    - 痕迹类型
      - 空间使用痕迹
      - 移动痕迹
      - 生态变化痕迹
      - 行为活动痕迹
      - 建设维护痕迹
      - 关系互动痕迹
      - 事件影响痕迹
      - 时间流逝痕迹
      - 情绪与关注痕迹
    - 移动痕迹的演化
      - 一次经过：形成弱痕迹
      - 重复经过：痕迹增强
      - 长期使用：区域移动成本可能下降
      - 长期不用：痕迹衰减或被生态覆盖
      - 被维护：痕迹变得更稳定、更清晰
    - 痕迹影响
      - 影响移动成本
      - 影响行为概率
      - 影响区域熟悉度
      - 影响生态恢复或衰退
      - 影响管家判断
      - 影响宠物安全感
      - 影响世界表现
