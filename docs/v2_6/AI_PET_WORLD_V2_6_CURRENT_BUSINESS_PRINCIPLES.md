# AI-PET-WORLD V2.6｜当前业务原则

> 本文档只描述当前确认的业务原则，用于约束 M11 核心资源库 / 验算库、后续正式画图算法与端游式 `/world` 主世界恢复。
>
> 本文档不记录历史路线，不把旧方案作为当前依据。

---

## 1. 一句话定义

AI-PET-WORLD 是一个以 AI 管家为核心自主行动者、由世界规则和资源系统驱动、通过痕迹与时间线持续演化的 AI 自主世界。

用户创建的是世界。

管家在世界中自主观察、判断、建设、等待、维护、解释和联络。

世界通过规则、资源、空间、痕迹、记忆、时间线和未来生命关系持续成长。

---

## 2. 产品本质

AI-PET-WORLD 不是传统养宠游戏，不是网页卡片产品，也不是单纯 AI 聊天工具。

当前产品本质是：

```txt
AI 世界
AI 管家
世界规则
层级划分
运行算法
世界资源
UI 自动生成算法
P-Phone 通信入口
```

世界不是背景板，而是具有事实、资源、空间、痕迹、状态和长期变化能力的运行系统。

画面不是世界本体。画面只是世界事实、规则、痕迹、生命状态和时间线的表现结果。

---

## 3. 用户定位

用户是世界源头，不是直接操控者。

用户通过创建世界启动 AI-PET-WORLD。

用户不直接控制管家行为，不直接控制未来宠物行为，不直接点击生成世界事实。

用户对世界的影响应通过正式入口、P-Phone、长期关系、轻影响事件和世界规则验证后产生。

---

## 4. AI 管家定位

AI 管家是当前世界里的核心自主行动者。

管家不是玩家鼠标，不是按钮执行器，也不是网页状态说明卡。

管家应具备：

```txt
自主观察
自主判断
自主建设
自主等待
自主维护
自主解释
自主记录
自主联络
长期成长
```

管家行为必须受到世界规则、资源状态、空间状态、痕迹状态、记忆状态和当前阶段约束。

管家可以影响世界，但不能绕过规则直接改写世界事实。

---

## 5. create-world 的业务含义

`create-world` 创建的是世界，不是宠物。

创建世界后，系统应建立：

```txt
世界身份
用户源头信息
管家初始存在
世界初始空间
世界初始资源
世界初始生态
运行保存记录
只读正式入口
```

`create-world` 不承担未来生命入场流程。

`create-world` 不承担正式像素主世界恢复。

`create-world` 当前只负责建立可被 runtime、WorldViewModel 和后续正式画图算法读取的世界起点。

---

## 6. 宠物定位

宠物是未来世界中的独立生命角色。

宠物不是默认资产，不是画面占位物，不是 create-world 的自动产物。

未来宠物进入世界，应通过正式世界逻辑发生，例如：

```txt
世界阶段成熟
小镇或领养中心开放
管家自主判断
资源与空间满足
关系条件满足
用户通过 P-Phone 参与轻影响
规则验证通过
```

不同管家可以做出不同选择。

有的管家可能主动去领养宠物。

有的管家可能选择等待、观察或暂时不领养。

这些差异应由 AI 管家人格、世界状态、资源条件、记忆、痕迹和规则共同驱动。

---

## 7. P-Phone 定位

P-Phone 是正式体验的一部分，不是 Debug 面板，不是后台审计工具。

P-Phone 的业务定位是真实手机式关系入口。

它可以承载：

```txt
用户与管家联络
管家主动联系用户
短信
电话
语音
世界通知
关系记录
未来 APP
未来管家之间联络
未来世界机构服务入口
```

未来部分 APP 不需要全部由开发者写死。

当世界发展到对应阶段后，管家、世界机构或 AI 文明倾向可以推动新 APP、服务和联络方式出现。

P-Phone 的核心不是控制管家，而是建立用户与 AI 世界的长期关系通道。

---

## 8. 世界建设原则

世界建设不是用户点击建造。

世界建设应由以下因素共同推动：

```txt
世界阶段
资源状态
空间状态
管家判断
痕迹积累
历史事件
长期目标
规则验证
```

管家可以建设、整理、维护和等待。

世界也可以因为时间、生态、痕迹和未来生命行为持续变化。

任何正式世界变化都必须经过规则验证，并沉淀为可追踪的事实、痕迹、事件或记忆。

---

## 9. 小镇 / 公园 / 医院 / 多用户定位

小镇、公园、医院、多用户都是后置方向。

它们不是当前 M11 要开发的功能。

未来这些模块也不应成为用户直接摆放的网页功能按钮。

它们应由世界发展、管家自主建设、世界资源、机构规则、生命关系和长期事件逐步推动。

未来小镇可以包含领养中心。

未来公园、医院和机构服务可以成为 AI 世界长期发展后的设施与关系节点。

未来多用户应服务于跨世界关系、管家通信、机构服务和长期世界资产，而不是提前压进当前 MVP 主链路。

---

## 10. UI 与正式主世界原则

未来 `/world` 是端游式像素主世界。

正式 `/world` 不应是网页卡片页，不应是 Debug 面板，不应是工程验收页。

正式画面链路应是：

```txt
WorldRuntimeSaveRecord
+ HomeMapState
+ SpaceGrid
+ TraceField
+ ButlerState
→ WorldViewModel
→ PixelWorldView
→ Tile / Trace / Object / Sprite / Atmosphere / UI Overlay
```

UI 自动生成算法必须读取世界事实和表现模型。

UI 不得自己生成世界事实。

P-Phone、管家一句话、必要状态可以作为 UI Overlay，但不能覆盖或替代主世界画面。

---

## 11. 当前 M11 工程重点

当前 M11 工程重点是核心资源库 / 验算库深化。

下一步只补输入边界，不恢复正式画面：

```txt
Actor 表现输入边界验算
P-Phone 数据入口边界验算
UI 自动生成输入边界验算
核心资源库 / 验算库 closeout
```

完成后再进入：

```txt
正式画图算法重整
→ 端游式 /world 主世界恢复
→ MVP closeout
```

---

## 12. 当前阶段工程红线

当前阶段必须遵守：

```txt
不做 M8 / M9 / M10
不做宠物学习
不做小镇 / 公园 / 医院正式运行
不做多用户正式运行
不恢复网页卡片主页
不恢复旧 /world 画面
不把 Debug Composer 搬进 /world
不恢复历史旧生命入口路线
不恢复 road/path 正式架构
不让页面访问推进 runtime tick
不让 derived_visual_only 写入 HomeMapState
不暴露 TraceField / AuditSummary / WorldViewModel / SafeApply 等后台词到正式 UI
```

这些红线不是业务内容本身，而是为了保护当前 M11 主链路不被旧方向污染。

---

## 13. 后续判断标准

后续所有模块都应先问：

```txt
它是否服务 AI 世界自主运行？
它是否服务 AI 管家自主判断？
它是否经过世界规则验证？
它是否能沉淀为世界事实、痕迹、记忆或表现输入？
它是否会破坏用户不是直接操控者的原则？
它是否会把正式 /world 拉回网页卡片或 Debug 页面？
```

如果答案不符合当前原则，则不进入当前主链路。
