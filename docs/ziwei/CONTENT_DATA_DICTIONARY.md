## 数据字典边界

1. 数据字典解释星曜、宫位、组合、格局和主题链，不直接等于当前盘结论。
2. 当前盘展示只显示盘中命中的内容。
3. 未命中格局、未触发规则只保留在字典，不进入当前盘结果。
4. 资料扩充必须补 `sourceReferences`。
5. 资料内容必须是公版古籍、项目原创整理、用户自有输入，或可安全保存的结构化摘要。
6. 数据字典不得重复定义星曜目录、格局目录、四化表、庙旺落陷表或动态盘规则。

| `storage-boundary` | `source-storage-boundary.dictionary` | 来源边界、复核队列和入库门禁 |

边界：数据字典是资料库，不等于当前盘结论；当前盘只读取盘中命中的内容。四化只按四化主题处理，不写庙旺；杂曜是否进入亮度表必须有独立来源和复核。

## P35-E 入库门禁

P35-E 已把资料筛选分成 5 类门禁策略：

| 策略 | 入库状态 | 适用资料 |
|---|---|---|
| 公版古籍可入字典 | `admitted` | 已确认来源、版本、篇目和实体引用的公版资料 |
| 目录索引仅保留元信息 | `metadata-only` | 古籍目录、馆藏目录、现代书籍索引 |
| 现代资料主题复核后入库 | `review-required` | 网站、视频、现代资料自有摘要 |
| 动态盘差异复核后入库 | `review-required` | 排盘软件差异、人工动态盘样例 |
| 禁止入库 | `rejected` | 现代正文、截图、扫描图、受限来源、未脱敏个人资料 |

每条入库决策必须记录 `cleanedResultId`、`policyId`、`score`、`admissionStatus`、`targetDictionaryLayer`、`requiredReviewQueueId`、`acceptedEvidenceFields`、`rejectionReason`、`nextAction` 和 `auditTrail`。

## P35-F 分析与页面使用

P35-F 只接入通过 P35-E 门禁后的资料，不新增理论内容。

| 使用层 | 页面可见性 | 边界 |
|---|---|---|
| 星曜字典详情 | `dictionary-only` | 可展示通用星曜资料，不等于当前盘结论 |
| 当前盘命中星曜分析 | `chart-hit-only` | 必须在当前盘实际出现，必须能回到星曜、宫位和盘层 |
| 格局命中分析 | `chart-hit-only` | 必须被格局算法确认，未命中格局不展示 |
| 动态流限分析 | `review-panel` | 未复核资料只进复核面板，不直接写成当前盘断语 |
| 拒绝资料审计 | `hidden` | 禁止进入解释正文和当前盘展示 |

页面展示规则：数据字典可以看全量资料；当前盘页面只展示盘中命中的资料；复核资料不自动进入当前盘；拒绝资料只保留审计记录。

## 资料采集批次

资料采集批次是给程序自动采集使用的计划，不是把资料直接写入解释正文。当前已定义：

| 批次 | 状态 | 方式 | 范围 |
|---|---|---|---|
| 公版古籍字典种子批次 | `ready` | 半自动 | 公版古籍正文、星曜、宫位、格局、四化、天干地支 |
| 馆藏与现代书籍元信息批次 | `ready` | 自动 | 大学图书馆馆藏目录、现代书籍元信息 |
| 网站与视频主题复核批次 | `planned` | 半自动 | 网站、视频的主题摘要和实体复核 |
| 动态盘差异与人工样例批次 | `planned` | 手动 | 排盘软件差异、人工校盘样例、动态盘复核 |

程序采集必须先产出来源登记，再进入片段、清洗、主题映射、入库决策和复核队列；不能绕过 P35-A 到 P35-F 的门禁。

### 程序执行器

当前执行器是 `p35.collection-executor.ziwei-v1`，负责把 4 个采集批次和 7 个来源种子展开成 7 条任务记录。执行器只生成任务、字段边界和审计链，不做正文抓取。

| 步骤 | 说明 |
|---|---|
| `load-batch` | 读取批次计划和来源种子 |
| `register-source` | 生成来源登记任务 |
| `capture-fragment` | 采集允许字段或项目自有摘要 |
| `clean-fragment` | 进入清洗、去重、冲突检测 |
| `map-topic` | 映射到星曜、宫位、地支、格局、四化、动态盘等主题 |
| `decide-admission` | 按 P35-E 门禁决定直入、元信息、复核或拒绝 |
| `route-review` | 进入来源复核、主题复核、动态盘复核或冲突复核队列 |

执行任务继承 `requiredFieldIds`、`allowedCaptureFields`、`forbiddenCaptureFields`、`expectedOutputs`、`storageGuardrails` 和 `reviewQueueId`。`ready` 批次生成 `ready` 任务，`planned` 批次生成 `queued` 任务；任何任务都不能绕过来源登记、存储边界和复核门禁。

### 真实采集适配器骨架

采集适配器只生成作业草案，不执行网络请求。当前按来源类型定义 7 个适配器：

| 适配器 | 来源 | requestMode | 边界 |
|---|---|---|---|
| 公版古籍文本适配器 | `classic-public-domain` | `public-domain-text` | 只处理已确认公版的古籍文本，不混入现代整理版正文 |
| 馆藏目录元信息适配器 | `university-library-catalog` | `metadata-only` | 只采目录元信息，不采扫描图、全文、受限影像 |
| 现代书籍元信息适配器 | `modern-book-metadata` | `metadata-only` | 暂不采现代书籍正文，只保留书名、作者、版本、目录线索 |
| 网站主题自有摘要适配器 | `website-metadata` | `own-summary-only` | 不存整篇网页正文，只写项目自有摘要和页面定位 |
| 视频主题自有摘要适配器 | `video-metadata` | `own-summary-only` | 不存字幕全文、课程讲义和会员内容，只记录时间点和自有摘要 |
| 排盘软件差异摘要适配器 | `software-reference-metadata` | `metadata-only` | 不存截图、图标、商标和版式，只记录功能差异 |
| 人工脱敏样例适配器 | `manual-sample` | `manual-input-only` | 只接收用户自有输入，样例必须脱敏，单一样例不能升为通用理论 |

### 采集实现入口

执行任务当前会派生 4 类程序输入：

| 输出 | 当前数量 | 作用 |
|---|---:|---|
| 来源登记草案 | 7 | 先登记来源、定位模板、存储策略、必填字段和禁采字段 |
| 片段采集输入 | 7 | 只给采集器允许字段，不提供抓取正文的入口 |
| 清洗输入草案 | 7 | 接入去重字段、冲突信号、清洗 pipeline 和预期输出 |
| 复核队列草案 | 6 | 所有带 `reviewQueueId` 的任务进入复核，不直接进入解释正文 |
| 真实采集作业草案 | 7 | 连接适配器、来源登记、采集输入、清洗输入和复核门禁 |
| 采集运行批次 | 1 | 汇总 7 条作业，当前为 `partial-ready` |
| 运行结果草案 | 7 | ready 作业为 `ready-to-run`，planned 批次作业为 `waiting` |
| 阻断审计记录 | 7 | 当前逐作业记录 `clear` 或 `blocked`，保留禁采字段和解除路径 |
| 采集审计输出 | 8 | 1 条运行批次审计 + 7 条作业审计 |
| 来源登记结果候选 | 7 | 由运行结果生成，不等于正式来源登记结果 |
| 片段结果候选 | 7 | 只保留允许字段路径和禁采字段，不保存现代正文 |
| 清洗结果候选 | 7 | 等待真实采集结果进入清洗 pipeline |
| 主题映射候选 | 7 | 先映射目标字典层，暂不写入正式字典 |
| 入库决策候选 | 7 | 标注 admitted、metadata-only、review-required 或 rejected 的候选状态 |
| 复核路由候选 | 7 | 标注是否需要进入复核队列 |

这一步只是把任务转成程序可消费的输入结构；真实网络采集、OCR、截图采集、现代资料正文采集都不在这里执行。

### 采集运行器

采集运行器读取 `ZIWEI_DATA_COLLECTION_JOB_DRAFTS`，但不直接发起网络请求。它只负责把作业分为：

| 状态 | 数量 | 说明 |
|---|---:|---|
| `ready` | 3 | 公版古籍、馆藏目录、现代书籍元信息批次已 ready，可交给适配器执行 |
| `draft` | 4 | 网站、视频、软件差异、人工样例批次仍是 planned，等待批次转 ready |
| `blocked` | 0 | 当前没有实际阻断作业；仍保留 7 条阻断审计记录证明禁采字段已检查 |

运行器输出不等于入库结果。真实采集完成后，还必须继续生成清洗结果、主题映射、入库决策和复核记录，才能进入数据字典。

### 真实采集结果落库草案

落库草案仍是候选层，不进入正式解释字典。当前链路为：

```txt
runResult
  -> sourceResultCandidate
  -> fragmentResultCandidate
  -> cleanedResultCandidate
  -> topicMappingCandidate
  -> admissionDecisionCandidate
  -> reviewRouteCandidate
```

候选状态与运行结果同步：ready 作业生成 `candidate-ready`，planned 批次生成 `waiting-for-run`，blocked 作业生成 `blocked`。只有真实采集完成、清洗通过、P35-E 入库门禁通过后，候选才允许晋级为正式数据字典资料。

### 候选晋级门禁

候选晋级门禁不采集资料，也不写正式解释正文，只负责判断候选下一步：

| 决策 | 含义 |
|---|---|
| `promote` | 可以晋级为正式资料记录，但仍必须保留来源追踪 |
| `metadata-only` | 只能保留元信息，不进入解释正文 |
| `review-required` | 必须进入复核队列，复核前不得晋级 |
| `reject` | 只能保留审计，不进入资料库正文 |
| `wait` | 等待运行批次或采集结果，不允许提前晋级 |

当前已建立 6 个门禁 profile：

| 门禁 | 作用 |
|---|---|
| `source-result` | 来源登记结果晋级门禁 |
| `fragment-result` | 片段结果晋级门禁 |
| `cleaned-result` | 清洗结果晋级门禁 |
| `topic-mapping` | 主题映射晋级门禁 |
| `admission-decision` | 入库决策晋级门禁 |
| `review-route` | 复核路由晋级门禁 |

当前 42 条落库候选均已生成晋级决策。`metadata-only` 决策永远不写入正式解释正文；`review-required` 决策必须保留 `reviewQueueId`；`waiting-for-run` 候选只能得到 `wait` 决策。

## 当前收口边界

资料采集批次到这里先收口。当前目标不是继续研发采集后台，而是把已完成的紫微斗数内容用于页面验收和人工缺口检查。

已经完成并可验收的紫微内容包括：星曜本体、主星辅曜杂曜分类、庙旺落陷、十二宫、十二地支、十天干、五行局、四化、格局/破格/不良格局、星曜组合、宫位主题链、原盘和动态盘解释。

采集结构只作为后续增强保留：字段模板、来源种子、批次计划、适配器、执行器、运行器、落库候选和晋级门禁都已经有基础结构；当前不继续实现真实抓取、自动采集后台、现代资料正文入库或自动写解释正文。
