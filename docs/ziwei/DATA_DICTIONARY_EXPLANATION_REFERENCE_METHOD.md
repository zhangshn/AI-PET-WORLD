## 定位

本文件记录如何参考 `ziwei.my` 这类现代紫微斗数资料站的解释方式。

这里参考的是资料组织方法，不是复制正文。现代网站资料只允许进入元信息、栏目结构、主题标签和项目自有摘要层；不得把网页正文、截图、排版、按钮、图片或整段解释直接写入项目数据字典。

## 参考到的解释方法

参考资料站的解释方式大体不是“一颗星一句话”，而是按以下层级展开：

| 层级 | 解释目的 | 我们的数据字典落点 |
|---|---|---|
| 基础体系 | 解释紫微斗数、阴阳五行、南北斗、中天星、十二宫、三方四正等基础概念 | `foundation.dictionary` |
| 星曜本体 | 解释单颗星曜的五行、阴阳、化气、象义、优势、风险和误读边界 | `star.dictionary` |
| 星曜入宫 | 解释同一颗星在十二宫中如何转换含义 | `star-palace.dictionary` |
| 十二宫系统 | 解释各宫位的人事主题、观察问题、对宫和三方四正关系 | `palace.dictionary` |
| 关系结构 | 解释同宫、对宫、三方四正、夹宫、会照和组合权重 | `relationship.dictionary` |
| 四化 | 解释四化由天干触发，区分本命、大限、流年、流月、流日、流时 | `transformation.dictionary` |
| 动态盘 | 解释原盘、大限、流年、流月、流日、流时的时间尺度和继承关系 | `dynamic-flow.dictionary` |
| 当前盘综合 | 只显示当前盘命中的星曜、宫位、格局、四化、三方四正和动态层证据 | `current-chart.analysis` |

## 转化规则

以后参考现代资料站时，必须按这个方式转成项目资料：

1. 先登记来源：页面地址、标题、栏目、涉及星曜、涉及宫位、涉及格局、主题标签、访问日期。
2. 再写项目自有摘要：只总结资料组织方式和主题覆盖，不复制原句。
3. 再映射字典层：判断属于星曜本体、星曜入宫、宫位、组合、四化、动态盘还是当前盘综合。
4. 再写证据字段：保留 `sourceId`、主题标签、实体标签、复核状态。
5. 最后进入复核：现代资料不能直接成为硬规则，必须能被公版古籍、项目既有规则或人工校盘样例支撑。

## 当前盘输出顺序

当前盘解释必须按以下顺序生成，不得直接从字典段落跳到断语：

1. 当前盘层：原盘、大限、流年、流月、流日或流时。
2. 当前宫位：本宫、对宫、三方四正、夹宫、会照。
3. 命中星曜：主星、辅曜、煞曜、杂曜、周期流系星曜。
4. 星曜状态：庙旺落陷只修正星曜，不给四化使用。
5. 四化来源：谁的四化、来源天干、目标星、目标宫。
6. 地支空间：四马、四败、四墓库、三合局、六冲、六合、刑害。
7. 格局命中：只显示已命中的格局，未命中格局不显示。
8. 综合解释：先列证据，再给解释，资料不足则隐藏或进入复核。

## 禁止事项

| 禁止项 | 原因 |
|---|---|
| 复制现代网站正文 | 现代网站内容只作为元信息和结构参考 |
| 复制截图或页面排版 | 页面资产不属于项目资料 |
| 把单站观点升为硬规则 | 必须有来源复核和多证据支撑 |
| 把星曜本体当成当前盘结论 | 当前盘必须命中星曜、宫位和关系结构 |
| 把流月、流日、流时放大成长期命格 | 短周期只做触发和提醒 |
| 把总字典全文塞进盘面解释 | 当前盘只显示命中的结果 |

## 验收边界
